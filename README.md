# dsh-visible-workflows

在 DeepSeekHarness 中管理、编辑和执行工作流。界面复用宿主主题与控件，画布布局和操作参考 Dify；产品要求见 [PRD v0.0.1](PRD-v0.0.1.md)、[PRD v0.0.2](PRD-v0.0.2.md)、[设计文档](设计文档.md) 与 [Dify 节点执行规格](docs/Dify节点执行规格.md)。当前实现包含 20 种有执行语义的节点，尚未完成 Dify 全量对标。

当前版本为 **v0.0.3**（2026-10-31 公开预发布），本地 Desktop 部署、实际验收和未完成项以[规划引擎 Tasks](doc/workflow-manual/规划引擎/设计/tasks.md)为准，变更见[版本记录](CHANGELOG.md)。当前源码包含类型化字段修改、后端模板实例化、稳定 ID 局部接线、受控规划补全及事件等待；功能通过与整体提速分别验收，历史性能失败保留。仓库名称为 `dsh-visible-workflows`；为兼容已有安装，npm 包名和宿主插件标识继续使用 `dsh-visible-dynamic-workflows`。

当前按钮、操作流程、20 类节点与 Graphon 执行边界见 [工作流原子手册](doc/workflow-manual/README.md)；早期验证见 [验证报告](doc/workflow-manual/验证/01-验证范围与结果.md)。v0.0.2 的两轮实现、测试与真实 Desktop 证据分别记录于 [PRD v0.0.2 实现与验收](docs/PRD-v0.0.2-实现与验收.md)，源码能力不代表发布包或真实模型已完成验收。

## 当前能力

以下描述当前开发源码。v0.0.2 的范围和验收见 [证据驱动优化执行方案](doc/workflow-manual/规划引擎/16-v0.0.2证据驱动优化执行方案.md)，变更与旧代码退役见 [版本记录](CHANGELOG.md)。自动测试和历史包验收不能替代 v0.0.2 的真实模型与实机验收。

- 工作流卡片主页、搜索、运行状态筛选、工作区筛选、创建、复制、归档和恢复。
- 所有入口统一在原生右侧栏打开，放大与收回沿用宿主全屏能力；节点多选使用高亮边框，不显示勾选框。
- 节点菜单与工具目录、连线与分支出口、拖动、框选、平移、缩放、整理、便签、撤销与重做。
- 标题后提供保存和另存为图标，支持 `Cmd/Ctrl+S` 与 `Cmd/Ctrl+Shift+S`。保存时图标旋转，完成后提示已保存；配置检查与保存联动，只有检查出问题才提示，画布编辑不再每次触发检查警告。设置可选手动或自动保存，自动保存默认每 5 分钟一次，可设为 1–1440 分钟；执行前始终先保存。缺少配置仍可保存，点击执行时提示补齐。另存为保留画布、批注和普通变量，创建独立流程，Secret 仅复制声明，不继承凭据或授权。
- 独立执行按钮直接启动 Graphon 图运行器，不要求主对话 Agent 推理。缺少必填输入时显示询问框；运行中的人工介入使用单独的等待状态与行动按钮。
- 节点真实输入、输出、状态、运行历史、容器轮次与取消；未激活的分支标记为“已跳过”。人工介入恢复复用已成功执行的记录，不重新调用先前完成的模型或工具。
- 角色预设只包含名称和角色提示词，在设置中统一管理。Agent 节点采用已确认的方案 B：角色提示词存入工作流的子 Agent 定义，节点单独保存本次任务提示词。选择预设时复制提示词快照，后续预设修改不会自动跟随，需显式点击“更新预设内容”；其他模型节点沿用原有预设机制。当前运行保留已冻结的提示词快照，暂停后显式应用运行修订才采用新快照。
- Agent 节点的子 Agent 卡片支持输入名称、下拉选择和新建；仅当名称与已有定义不同时显示新增动作。每个定义有独立 ID、编号和名称，绑定当前工作流及当前主对话，同一范围内可重复引用。JSON 用 `subAgents[]` 保存共享定义和角色提示词，节点用 `config.subagentId` 引用，以 `config.prompt` 保存任务提示词；每次执行仍生成独立的宿主原生任务，不把逻辑定义 ID 当作原生任务 ID 或跨次会话记忆。
- 模型节点未单独指定模型时跟随 DSH：优先当前工作区对话所选模型，否则使用宿主默认模型。已有具体模型不被覆盖，实际模型与强度在本次运行中固定；不需要重复配置密钥。
- 主 Agent 可通过专属工具读取、生成和启动后台流程；修改已有流程产生待接受提案。Host 检查工作区、固定节点与乐观版本，保护也覆盖容器。
- 结构编号随图结构调整，支持分支、汇合与嵌套容器；执行变量和注释使用稳定节点身份。
- 对话引用和注释接入宿主输入框；提交先进入草稿，用户发送后才交给 Agent。
- 侧栏“高级设置”采用节点菜单的视觉样式，提供“环境变量 / 全局变量 / 执行策略”三个页签，取代右上旧入口。环境变量明确分为字符型、数字型和密钥，前两类可被 Agent 读取，仅密钥通过声明和受控引用使用；普通变量编辑不依赖 Secret 可用状态。全局变量沿用只读 `sys` 命名空间，由运行器生成。
- macOS Secret 沿用系统 Keychain 与独立原生管理窗口，用户可查看、编辑和删除；自动使用授权持续有效直到撤销，修改凭据或目标后需要重新授权。工作流、日志和 Agent 接口不提供原值。上一阶段 rc.1 的管理、固定请求和 JSON 往返实机证据保留于[验收记录](doc/workflow-manual/验证/10-DSH021适配与Secret管理请求验收.md)，具体能力和限制见[变量级保护边界](doc/workflow-manual/原理/11-Secret变量级保护边界.md)；本轮 rc.2 尚待实机核验，Windows 仍为未编译的源码候选。
- 侧栏统一“导出”按钮向右展开菜单，选择流程 JSON 或 SVG；JSON 继续使用现有传输面板，保留 JSON/ZIP/Markdown 相关能力和普通变量值的显式导出选项。JSON/ZIP 导入保留独立入口，保留节点、位置、视口、便签和批注；缺失模型、工具、外部流程、文件或变量以待处理项引导补齐，进入画布后可继续编辑和保存。默认导入为新流程，覆盖须确认目标版本，保留原运行记录。字段详情见 [JSON 字段与导入导出](doc/workflow-manual/原理/10-JSON字段与导入导出.md)。
- 工作流 JSON 以该字段说明为唯一标准：包只接受 `formatVersion: 2`，执行协议为 `graphon / 1`；不再支持旧包版本或旧字段自动迁移。Agent 节点只通过 `config.subagentId` 引用 `subAgents[]`，节点级 `config.rolePresetId` 被拒绝；未选择定义仍可保存为待配置。其他模型节点的合法预设字段保留，历史验收记录不代表当前格式兼容承诺。
- 工作流不再设置 Token 总额、单任务额度或累计 Agent 任务配额，规划和发布不询问预算。执行策略保留并发及有限修复控制，运行详情分别显示实际用量、未知调用和待回执。旧额度字段仅兼容读取，历史文件原样保留。内置/个人模板、归档恢复、暂停继续及历史快照重跑沿现有画布和流程库接入。
- 恢复前逐执行实例展示复用、重做或阻断原因，确认后校验同一计划；暂停根运行可预览并应用画布修订，保留旧快照、运行身份和实际用量，应用后仍暂停。
- 运行详情可查看原生 Agent 实际事件摘要、补充指令和修复记录；补充指令向原任务投递并记录实际用量，稳定消息 ID 避免重复提交；独立画布运行默认先确认候选修复，只有宿主可信授权可自动修复；空工具修复累计最多两轮，汇总实际用量，不重放原动作。确认模型修复后仍暂停，由用户继续。
- 工作流子 Agent 使用原生工具模式，在首轮请求前绑定工具，并在实际调用入口再次校验白名单。子 Agent 不继承 PTC `run_code` 通用执行能力，也不能隐式派生后代任务；此限制仅作用于工作流子 Agent，不改变主会话设置。

## Agent 辅助规划后端

规划修改使用[局部编辑意图与宿主编译](doc/workflow-manual/规划引擎/17-局部编辑意图与宿主编译.md)：模型提交指定字段或局部结构操作，Host 根据稳定 ID、临时引用和冻结版本拼装 Workflow JSON。确定修改无需新增规划模型调用；未决字段继续使用 canonical edit 合同，经过相同的权限、范围与完整图校验。单字段 `complete-field` 协议仅保留为显式实验：真实五对样本均正确，但配对中位耗时增加 13.00%，已撤回自动启用。历史任务仍可读取；实际性能以 Tasks 中冻结的配对实验为准。

规划问题由 Host 原生问答接管时，`get/wait` 明确返回 `native-pending`，主 Agent 不复制提问或猜测问题版本；仅手动入口就绪时才转交 `plan_answer`。真人回答按同一任务、问题全文和批次绑定，续接子 Agent 能区分首次提问与本次已答信息。部署及真实语义验收状态见 [当前 Tasks](doc/workflow-manual/规划引擎/设计/tasks-规划提速与上下文复用.md)。

**v0.0.2** 在“从本次任务生成工作流”中加入基线保留、最多两轮确定性替换、真实 Graphon 节点片段回放和优化前后对比。只替换有完整历史样本支持的顶层模型节点；无证据、验证失败、无收益或运行调用目标仍超出时保留有效候选。对比通过原生对话返回，不增加独立规划卡片。调用次数目标用于优化评估；发布权限及人工审核继续独立检查。详情见 [v0.0.2 执行方案](doc/workflow-manual/规划引擎/16-v0.0.2证据驱动优化执行方案.md) 与 [版本记录](CHANGELOG.md)。

`/dsh-visible-workflows` 将需求交给当前 Agent 的正常对话；“交给 Agent”生成的聊天草稿发送后，以及明确要求优化当前工作流时，也由主 Agent 调用 `visible_workflow_plan`。追问、执行过程和结果使用宿主原生对话，不显示独立规划卡片。引擎基于当前 Workflow JSON 生成精简候选，Host 补齐并验证；新建保存可编辑图，修改提交待接受提案，业务执行继续使用 Graphon。支持问题补充、最多三次候选、取消、幂等回执及只读预览。任务立即返回 taskId；主 Agent 通过 visible_workflow_plan_wait 等待可核验结果后汇总，本插件同时在回合结束前等待当轮关联规划任务。实际用量与未知回执分别记录，业务澄清和真人质量复核继续保留。

实现、官方 0.2.1 接口审计、容量限制与验收边界见[执行方案](docs/Agent辅助生成工作流后端引擎执行方案.md)。2026-10-18 已将本地 fix5 包安装到 macOS Desktop **0.2.1-rc.2**，用 **GLM-5.3-Flash** 验证三个规划入口、正常对话中的原生询问、执行过程展示及会话预算规则；详细结果、一次被拒绝并纠正的字段误改及数据保全范围见[实机验收报告](docs/工作流规划入口与会话预算实机验收-2026-10-18.md)。本地包未公开发布，其他模型及平台未据此验收。

2026-10-20 按用户要求移除本插件预算系统，保留实际用量与运行安全控制。上述 2026-10-18 预算验收属于历史行为；当前实现、兼容和 Desktop 验收状态以 [S12 Tasks](doc/workflow-manual/规划引擎/设计/tasks-规划提速与上下文复用.md)及[预算移除记录](docs/evidence/budget-removal-20261020/implementation.md)为准。

## 可执行节点

| 节点 | 当前实际行为与配置 |
| --- | --- |
| 用户输入 `input` | 声明文本、段落、数字、布尔、选项、JSON、文件和文件列表；检查类型、默认值与必填项。 |
| 大语言模型 `llm` | 通过宿主 `ctx.llm` 调用指定模型；支持角色提示词、模型支持的思考强度，以及具名结构化输出的类型检查。 |
| Agent `agent` | 选择或新建工作流内的子 Agent 定义，复用编号、名称和角色提示词快照，节点另存任务提示词。通过宿主原生 spawn 执行，使用独立上下文和明确工具名单；可编辑结构化输出字段，留空沿用文本默认；分别记录定义 ID 与原生任务 ID、实际用量及有限输出修复。 |
| 知识检索 `knowledge` | 从选定的工作区文档提取文本，按关键词匹配检索片段，应用分数阈值和 Top K，返回来源、片段与分数。 |
| 输出 `output` | 渲染模板并写入本次运行的命名输出。输出节点不会提前终止整个图；同名已激活输出明确报错，避免静默覆盖。 |
| 问题分类器 `classifier` | 调用模型选择已定义的类别 ID，只激活对应出口；无效类别或不合法模型响应会报错。 |
| 条件分支 `if` | 保留按顺序匹配 IF/ELIF/ELSE、AND/OR、文本与数值比较及空值判断；也可切换 IF/AND/OR/NOT/NAND/NOR/XOR/XNOR 逻辑门，默认严格 Boolean。 |
| 人工介入 `human` | 到达节点后暂停，冻结显示内容和预填字段，等待用户选择行动并补充输入；按行动或超时出口继续。没有字段时仍需用户选择行动。 |
| 迭代 `iteration` | 对数组实际执行内部子图，提供 `item` 与 `index`，按输入顺序收集结果；支持顺序或有上限的并发，以及失败终止、保留 null、移除失败项三种策略。 |
| 循环 `loop` | 跨轮保留循环变量，执行内部子图；由终止条件、最大轮数或退出循环节点结束。 |
| 退出循环 `exit_loop` | 终止所属循环的当前控制路径，随后返回外层图，不取消整个运行。 |
| 代码执行 `code` | JavaScript 在无宿主 I/O 绑定的 QuickJS WASM 环境运行 `main(inputs)`；Python 使用受限纯数据语法，并要求宿主提供完整文件沙箱。输出须为对象，可校验声明字段。 |
| 模板转换 `template` | 支持变量与嵌套字段、有界 `for`、`if/elif/else`，以及 `default`、`join`、`upper`、`lower`、`trim`、`length`、`first`、`last`、`tojson`、`replace`、`sort` 过滤器。 |
| 变量聚合器 `aggregator` | 每组选择互斥分支中实际产生的唯一值，保留 false、0、空串；多个有效来源会报错，不冒充并行结果收集器。 |
| 文档提取器 `document` | 本地轻量提取文本、Markdown、CSV/TSV、JSON/YAML/XML、HTML；PDF、DOCX、OCR 等通过明确选择的 DSH 工具/MCP 或 Agent 解析。批量返回合并文本和来源。 |
| 变量赋值 `assigner` | 对本次运行或循环局部变量执行覆写、清空、数值运算，以及数组追加、扩展、移除首尾。 |
| 参数提取器 `extractor` | 调用模型提取具名参数，检查必填与类型，输出参数及 `__is_success`、`__reason`。 |
| HTTP 请求 `http` | 实际发送 GET/HEAD/POST/PUT/PATCH/DELETE 请求，支持模板 URL、请求头、文本请求体、超时和取消；返回正文、状态码、响应头及可解析的 JSON。 |
| 列表操作 `list` | 过滤数组，对同类型字符串、数值或布尔值排序，取前 N 项；输出结果、首项和末项，空结果首尾为 null。 |
| 工具 `tool` | 根据实际目录调用内置工具、已导入的 Swagger/OpenAPI 操作、同工作区工作流，以及当前对话可访问的宿主插件或 MCP 工具。 |

### 变量与容器

使用 `{{input.text}}` 引用输入，使用 `{{节点稳定ID.text}}` 或 `{{节点稳定ID.具名字段}}` 引用节点结果。对象和数组可继续访问字段；代码等节点的字段以实际返回对象为准，并非每种节点都有 `text`。映射值恰好为一个 `{{变量}}` 表达式时保留 JSON 类型；插入普通模板文本时转换为文本。

`{{vars.count}}` 引用可写局部变量；迭代内部可用 `{{item}}`、`{{index}}`。容器配置保存真实子图 `body: { nodes, edges }`，子节点身份在整个工作流内唯一。结构编号如 `a-2` 只用于阅读，不能代替稳定 ID 作为执行引用。循环通过专用容器实现，图中的任意回边仍会被拒绝。

### 工具与外部依赖

工具目录中的时间、时区、时间戳和 JSON 处理操作可以独立执行。导入的 Swagger/OpenAPI JSON 文档会转换为可配置的 HTTP 操作；目录按工作区保存。工作流工具使用相同运行器，检查工作区和递归深度。

宿主插件与 MCP 工具复用实际注册目录和 `ctx.tools.execute` 调用管线，需要绑定当前工作区的有效对话权限。独立图运行不等于自动获得任意对话的工具权限，也不会绕过宿主审批。目录中不存在的工具或不满足依赖的能力会明确报错。

JavaScript 节点不提供文件、进程、网络或任意模块导入。Python 节点复用随插件预构建的解释器，仍要求宿主完整文件沙箱；缺少沙箱时不能运行。文档节点不再调用系统 Python 或隐式安装 PDF/Office 解析器；旧流程中需要这类解析的节点须选择可用的工具/MCP 或 Agent。模型相关节点均使用宿主已配置的提供方，失败时不会静默切换模型。

## Graphon 轻量执行环境

插件使用原版 Graphon 0.7.0 `GraphEngine` 管理依赖、分支跳过与合流；DSH 继续执行节点业务、管理变量和权限。迭代/循环的每个内部图也交给 Graphon。现有成功节点结果和运行快照用于人工等待后的恢复，避免重放外部动作；当前没有迁移到 Graphon 原生容器或原生检查点存储。主图默认允许 3 个 worker，最高 8 个；含人工介入或共享赋值的当前图保守顺序执行。模型及 Agent 还受单 Host 进程 8 个、同工作区 4 个及根运行策略的并发限制，子流程使用根运行的并发策略，并将实际用量汇总到根运行。

macOS Apple Silicon 安装包携带私有 CPython 3.12.15、受控核心依赖和离线 `cl100k_base` 词表。首次执行自动校验并解压，不依赖系统 Python、pip、uv 或首次联网下载。模型调用前记录轻量 token 估算；该值不等于所选模型的账单或精确上下文长度。运行环境归插件管理，不加入 PATH，不替代宿主代码沙箱。

文档节点提供“本地轻量解析 / 指定工具或 MCP / Agent 解析”选择。Agent 使用 DSH 模型与明确的工具白名单，必须实际读取来源后才能提交结果；附件按本次运行归属检查。工具参数与文本结果路径需要匹配所选解析服务，不会静默改用其他工具。模型、密钥与思考强度继续沿用 DSH 设置。

本次默认包仅携带 macOS arm64 资源；Windows x64 构建链和清单校验已准备，但必须在 Windows 实机验收后再分发对应包。Graphon 的完整依赖声明保留作来源记录，实际受控运行环境省略 Transformers、Unstructured、OCR/Office 解析栈；这不是可直接用 pip 安装的独立精简 Graphon 发行版。详见 [运行环境构建说明](runtime/packaging/README.md) 和 [本次接入验收](docs/Graphon轻量接入验收.md)。

需要 Node.js **22.19.0 或更新版本**及项目依赖。开发依赖固定使用 DeepSeekHarness **0.2.1-rc.1** SDK、Cordis **4.0.5** 和 Schemastery **3.18.5**，以保持可复现构建；该构建基线不作为宿主版本门槛。DSH 的 peer 依赖不限制版本，运行时能力检查继续保留。上一阶段 v0.0.1 已在 0.2.1-rc.2 完成实际接口核验、安装与原生子 Agent 调用，未覆盖的交互继续单独列明，不能据依赖声明推断其他版本已通过。插件包不包含完整宿主。克隆仓库后先使用 pnpm 11.25.0 执行 `pnpm install --frozen-lockfile` 安装开发依赖，再执行以下构建与测试命令。GitHub 既有 Release 的实测环境另见上方安装说明。

**开发验收入口是官方 Harness Web：`http://127.0.0.1:5188`。** 使用隔离配置目录 `.cache/harness-web-test` 加载完整 Host 和 Client 插件；如宿主启用会话认证，使用其启动输出提供的访问链接。工作流入口、原生菜单与设置、聊天草稿、注释、工具权限和真实独立运行，都应在这个宿主页面验收。此端口留给官方 Harness Web。

使用已安装的官方 DSH 启动真正 Web，并复用桌面端接入的模型：

脚本默认读取 `~/.dsh` 的 `desktop` profile，只向 `.cache/harness-web-test` 写入模型路由和默认选择；已配置凭证只传给本机宿主子进程，不写进项目或日志。可用 `--source-home`、`--source-profile` 指定实际配置来源，`--dry-run` 检查配置读取。工作流节点默认选择“跟随 DSH”，无需单独配置 API Key。

## Host 与 Agent 接入

Host 服务和 Remote namespace 为 `visibleWorkflows`。Agent 工具统一使用以下名称，与已有 `@dsh-external/workflow` 区分：

| 工具 | 用途 |
| --- | --- |
| `visible_workflow_list` | 读取当前对话工作区的流程与预设 |
| `visible_workflow_get` | 读取完整流程及当前版本 |
| `visible_workflow_current` | 读取当前对话画布目标，核验可见性、版本和未保存状态 |
| `visible_workflow_plan` | 受理规划请求并立即返回 taskId，后台生成新图或修改提案 |
| `visible_workflow_plan_wait` | 按事件等待同一任务的可核验结果；waiting 时继续等待，需真人输入时返回问题边界 |
| `visible_workflow_save` | 保存新流程；修改已有流程提交待接受提案，不启动执行 |
| `visible_workflow_run` | 使用独立运行器执行，缺输入或遇到人工介入时进入等待 |
| `visible_workflow_status` | 读取真实运行结果和错误 |
| `visible_workflow_cancel` | 停止运行并等待取消完成 |

工具只能操作当前对话实际所属工作区。Agent 保存和启动遵守宿主规划模式、只读策略与工具调用管线。Agent 自动创建 LLM、Agent、分类和提取节点时，默认沿用当前有效模型配置，并限制自动选择的思考强度；用户可以在节点面板手动覆盖。当前工具不提供修改全局预设或绕过固定保护的旁路。

默认持久化目录为 `$DSH_HOME/visible-dynamic-workflows`；未设置 `DSH_HOME` 时为 `~/.dsh/visible-dynamic-workflows`。目录权限为 0700，数据文件为 0600，单 Host 锁防止重复写入。运行记录保存图、角色提示词和执行结果快照。上传附件存放在私有目录，运行记录仅保存文件元数据及本次运行的附件身份；读取时检查运行归属，不能使用其他运行的附件 ID。

## 尚未全面对齐的部分

- **节点覆盖不等于 Dify 全量兼容。** 自动触发器、发布与部署、完整 DSL 往返兼容、多人协作、Chatflow 专用能力和 Dify 插件生态完整适配尚未完成。
- Agent 依赖当前宿主原生 spawn 提供方，接口能力不满足时明确失败。动态委派工具不在 Agent 节点允许范围内，子工作流通过显式工具节点管理。LLM 的视觉、记忆和完整参数面板尚未完整对齐。**自动测试的 SDK/模型替身不代表真实模型调用验收。**
- 知识检索当前采用本地文档关键词匹配，未实现 Dify 向量知识库、重排模型、多模态查询和完整元数据过滤。
- 模板是受限的 Jinja 数据语法子集，不支持任意函数、扩展或完整 Jinja2 环境。Python 也只支持受限纯数据语法，不提供任意包和 I/O 能力。
- 文档提取未覆盖 Dify 全部文件格式、OCR、音视频转录或复杂 Office 排版与表格恢复。批量文档提供合并 `text` 和逐文件 `documents`，与 Dify 多文件 `text` 数组契约不同。HTTP 当前为文本请求与响应，未完整支持二进制文件、multipart、认证管理、节点重试和全部错误分支策略。
- 变量赋值仅作用于本次运行或循环局部变量，不跨聊天会话持久化。含人工介入的迭代需采用顺序模式；包含人工介入的流程可独立执行，当前不能作为工作流工具调用。人工介入默认三天超时，尚未实现邮件等外部交付渠道。
- 保存编辑不会自动改变活动快照。已排空且没有待纠正输出或活动子运行的暂停根运行，可在差异预览后显式应用修订；旧快照保留，运行身份、输入与实际用量不重置，仍需手动继续。布局、名称和便签变化不会单独建立运行修订。
- 输出修复仅适用于已确认完成的 Agent 输出结构/长度问题，最多两轮、空工具、单独记录实际用量；修复轮次耗尽或并发准入失败时暂停并提供人工纠正，普通继续不能重放原动作。外部操作失败不自动重放，撤销图编辑不会撤销外部动作。
- 未知用量保持未知，不估成实际消耗，也不占用额度；旧 budget_waiting 以旧运行暂停状态兼容读取，可显式继续或停止。文件验证目前检查存在、可读及工作区路径归属，不能代替业务正确性验收。历史恢复对未知或不可复用的外部动作会阻止自动继续，须先核验。
- 同一流程只允许一次未结束运行，最多同时执行四个不同流程；每层图最多 200 个节点、1000 条连线，含子图合计最多 500 个节点、嵌套最多五层；一次运行最多 5000 个节点步骤。这些是实现限制，不是性能测试结论。节点文本与结果另有容量限制。
- Agent 对固定节点的一次定向授权尚无可信授权对象，本版保持保护；用户可在画布直接修改或解除固定。结构编号支持容器，但尚不支持用户指定主路径。

早期证据见 [MVP 验收说明](docs/MVP验收说明.md)，当前 v0.0.2 状态及未完成项见 [PRD v0.0.2 实现与验收](docs/PRD-v0.0.2-实现与验收.md)；此 README 不代替实际宿主验收。

### 上一阶段 Secret 方案验收（2026-10-17，DSH 0.2.1-rc.1）

以下保留上一阶段 Secret 包的历史实机证据，其中“新包”“本次”“本轮”均指当时的 rc.1 Secret 迭代，不代表本轮新增保存、高级设置、子 Agent 定义或 rc.2 适配已通过验收。上一阶段 v0.0.1 在 rc.2 已安装并完成部分桌面及原生调用核验，具体范围见[本轮记录](doc/workflow-manual/验证/11-保存高级设置与子Agent定义迭代.md)。

macOS 已在现有 Desktop 插件中接入系统 Keychain；用户通过独立原生窗口管理值，系统确认本人身份，原值不返回画布、Host 或 Agent。前轮用户实际保存测试值后，画布的 Secret 待配置提示消失；真实 JSON 导出再导入保留节点、位置、便签和批注，导入副本重新要求配置。适配 DSH 0.2.1 后，用户明确反馈看到旧值、修改保存成功，又确认“重开后是新值，已关闭窗口”；原生查看、编辑与持久化核对通过，未记录具体值。用户随后已确认原生删除，缺失提示恢复，执行按钮仍可点击并弹出处理提示；本阶段 CRUD 验收通过。

用户随后选择“一次授权持续有效，直到手动撤销；修改凭据或目标后重新授权”。持久授权源码已接入：管理窗口一次本人认证，五个动作分别为“仅保存”“保存并授权自动使用”“撤销自动使用”“删除”“关闭”；仅保存轮换 epoch 并撤销旧授权，保存并授权在同窗口完成。授权只保存在本机并绑定当前流程/变量与固定目标；未授权后台执行直接待配置、不弹窗、不请求网络。并发撤销修复及回归通过，新包已安装。用户一次保存并授权后，连续两次真实固定请求均未再次认证，分别耗时 1.677 秒和 0.988 秒，均只返回 `{ok:false,status_code:401}`。为减少重复交互，新包未另做人工撤销、修改后授权、删除或重启；这些限制与自动回归、旧版 CRUD 结果分别记录。

前轮真实主 Agent 与官方原生子 Agent 的 `visible_workflow_get` 均已成功并完成，Secret 只返回六个公开声明字段，没有原值；本次持久授权新包没有再次调用真实模型，不能写成重复通过。首轮子 Agent 工作区继承错误已修复，失败与重试证据分别保留；该结果只证明这条工作流接口和父子调用路径，不扩张成所有本机工具的 OS 隔离结论。

现有 HTTP 受控凭据协议只访问固定 DeepSeek `/user/balance`，仅返回 HTTP 状态码及其是否为 2xx，不返回正文、余额或请求头；已由用户批准并认证，真实固定请求返回 401；这证明请求与状态交付完成，不代表假测试值是有效 API 密钥。原生存储接受通用密码，固定消费者另行检查 Bearer 语法，不提供任意 API 插值。工作流 JSON、快照、草稿和 Agent 工具没有 Secret 原值接口；删除画布声明不会自动删除 Keychain 项目，当前需在原生管理中删除值。
