# Graphon 轻量接入验收

日期：2026-10-15。目标：复用原有 DSH 画布与工作流数据，接入复杂图调度核心，自动准备私有 Python 环境，文档解析交给 DSH 工具/MCP 或 Agent。

## 实际接入范围

- 原版 Graphon 0.7.0 `GraphEngine` 负责节点就绪、边激活、条件分支跳过和合流。自定义节点通过本机 JSONL 请求 DSH Host 执行，不是只导入 Graphon 后继续使用旧拓扑循环。
- 原有 20 种节点、稳定 ID、结构编号、图版本、固定节点、角色预设、模型继承、注释、便签、缩略图与运行历史继续沿用。运行记录新增 `engine` 来源。
- 迭代/循环保留原来的变量、轮次和错误策略，每个内部图调用 Graphon；并发迭代继续按上限执行多个内部图。每图单 worker，不声称一般分支已经并行执行。
- 人工等待由 DSH 保存运行快照、成功结果及表单，恢复时通过结果缓存避免重复模型/工具调用。未迁移到 Graphon 原生容器帧或原生检查点持久化。
- 引擎异常退出会取消在途节点，运行保持失败，迟到的模型/工具结果不得改写成功状态；后续新运行可重新启动引擎。取消不等于撤销已经发生的外部动作。
- 轻量分词使用离线 `cl100k_base`；模型节点调用前保存 token 估算。它不是所有模型的精确分词器，也不替代服务端 usage。

macOS ARM64 预构建环境包含 CPython 3.12.15、Graphon 0.7.0、28 项锁定 Python 包和离线词表。不包含 Transformers、Unstructured、OCR/Office 解析栈，也不使用 Slim 默认构造链。

首次执行自动校验、解压和离线启动检查，再原子写入就绪标记。此后复用私有目录，不查询系统 Python，不使用 pip/uv 自动补依赖，不修改 PATH。Python 代码节点也使用该解释器，但仍必须满足 DSH 完整文件沙箱要求。缺少沙箱时明确拒绝执行。

这是应用私有的受控依赖集合，保留上游 source、dist-info 和许可；不是新的独立 Graphon 精简 wheel。完整 Python 依赖声明仍含上游重型功能，因此不能将 `pip check` 当作此受控配置的完整性证明。

Windows x64 已生成单独的静态验证包（24,114,543 B；展开74,748,580 B），未加入默认 macOS 插件包。清单标注 `static-only` 和 `executed:false`；没有 Windows 实机执行结论。Linux 与 Intel Mac 暂未提供资源包。

## 文档解析

| 来源 | 当前实现 |
|---|---|
| 轻量本地 | 工作区路径或本次运行附件；UTF-8 文本、Markdown、CSV/TSV、JSON/YAML/XML、HTML。 |
| 指定工具 / MCP | 选择真实目录工具，设置文件参数名、附加参数和文本结果路径；校验输入输出及当前会话权限。 |
| Agent | 沿用 DSH 模型/强度/角色预设；仅允许选择的工具；每个来源必须先被实际读取，才能提交提取文本。 |

上传附件在调用工具前才解析为 `{name,mimeType,base64}`，模型收到来源引用和元数据；工作区本地文件向工具传经过验证的绝对路径。附件按运行归属检查。不可用的工具、错误结果路径或取消会明确停止，不静默替换解析服务。

旧 PDF/DOCX 本地解析配置需要改选工具/MCP 或 Agent；本次有意移除隐式系统 Python/pypdf 路径。已保存的节点和原文件没有删除。复杂格式的保真度依赖所选服务，未声称所有 Dify 格式均已逐一验收。
