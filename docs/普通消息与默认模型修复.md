# 普通消息提示词与默认模型修复

日期：2026-10-15。范围为用户反馈的普通聊天失败，以及工作流默认使用 DSH 已配置模型；不作为 Dify 全量完成的验收。

## 普通消息失败的原因

工作流插件注册的 `visible-workflows:guide` 包含 `{{input.字段名}}`、`{{稳定节点ID.text}}` 两段工作流变量示例。宿主系统提示词默认会把双花括号识别为自身变量；上述示例不符合宿主变量名称规则，因此普通聊天也会在请求模型前失败。

修复在该提示词段声明官方 SDK 的 `interpolate: false`，按原文保留工作流说明。工作流模板语法不变，其他提示词的正常变量插值仍受宿主校验。

回归测试使用真实 `SystemPrompt`、`ToolRuntime` 和生产 `VisibleWorkflowService`，覆盖 native、both 两种工具模式。实际组装并渲染通过；从实际组装段移除该标记会复现截图中的原错误。测试也检查生产工具定义与 `tools:sdk` 不损坏示例内容。该测试不调用外部模型。

## 工作流默认模型规则

- 未单独指定模型的节点跟随 DSH；有效同工作区对话的选择优先，无对话时使用宿主默认模型。
- 显式指定的节点模型保持不变。模型目录来自宿主，插件不额外索取密钥，不选目录第一项作为兜底。
- 启动时解析实际模型并保存至本次运行快照，包含循环、迭代子图及子工作流；不将运行默认值写回原工作流草稿。
- Agent 自动生成仍沿用当前执行 Agent 模型，自动选择的思考强度不能超过当前 Agent。用户手动指定的节点配置不被默认值覆盖。
- 未配置、已移除或不兼容的模型应明确报错，不悄悄改用其他模型。纯数据流程仍无需模型配置。
