## 1 对标口径与宿主适配

1. **所有画布编辑能力均保留**，包括多人编辑、持久评论、成员 `@`、片段、键盘操作、对齐和视图导出，不以用户截图中可见按钮代替完整范围。
2. 原有 A / B 布局决定不变：A 为左侧宿主导航，B 为主内容区；管理主页和卡片进入的画布占满 B，对话创建或引用默认在 B 右侧栏，可向左展开。下表的“右上”“底部”“面板”均相对于当前画布容器，不能强行占用整个应用窗口。
3. **便签、画布评论、给 Agent 的注释是三个对象**：便签是长期说明；画布评论支持协作与持久讨论；Agent 注释绑定节点、进入聊天草稿，发送成功后清除临时编号。不能为对齐 Dify 而恢复已发送的 Agent 注释编号。
4. 对标表示提供等价能力和可检查的结果，不要求复制 Dify 的页面位置、收费限制或品牌文案。用户已确认的固定节点保护、运行副本、模型配置、询问框等规则优先。
5. 下表“产品要求”和“验收动作”是面向本项目的需求细化；来源列说明 Dify 的可核验依据，不表示这些设计已在 DeepSeekHarness 中运行。
6. **设计风格统一采用 DeepSeekHarness**：设置、菜单、功能页以及画布内部的文字、间距、颜色、控件和状态反馈都遵循宿主规范；Dify 提供画布布局和完整能力基准。布局适配不删功能；视觉一致性另按设计文档 DS01—DS06 验收。

## 7 触发与发布边界 TRG / PUB

“画布全面对标”包含触发节点的创建、配置、测试、开关和真实调度依赖；不能只画出触发节点却没有对应执行方式。公开网站/API/MCP 服务、市场等属于与画布相邻的平台能力，下表明确列出，避免混在“导出”或“独立执行”里默认承诺。

| ID | Dify 官方行为 | 本产品要求与边界 | 验收动作 | 环境与限制 | 来源 |
| --- | --- | --- | --- | --- | --- |
| TRG-01 | Workflow 有用户输入或触发入口；Chatflow 无触发入口 | 明确手动型/事件型入口；手动执行可在未启动主 Agent 时运行 | 分别新建两类入口，检查可用运行方式 | 不为事件型流程伪造缺少事件数据的普通运行 | [D04][D04] |
| TRG-02 | 定时、集成事件、Webhook 三类触发；允许多个触发 | 三类均进入对标；实现须有调度/事件订阅/HTTP 接收服务 | 用受控事件触发一次，确认创建一条可追踪运行 | 同一 Workflow 最多一个定时触发；Dify Cloud 配额不作为本产品收费设计 | [D14][D14] |
| TRG-03 | 已发布触发可开关；关闭期间事件被忽略 | 显示生效状态、依赖在线状态和最近触发结果 | 关闭后发事件不运行，开启后新事件可运行 | 桌面关闭/休眠时能否运行取决于后台服务，必须在主 PRD 明说 | [D14][D14] |
