- 对应需求：[PRD](../PRD.md)。本文件补充宿主接入证据、设计契约、验证与排期，不修改已经确认的产品范围。
- 调查日期：2026-10-14。
- 调查方式：只读本机安装包、官方 SDK 文档与类型声明、同级 `cliworker-now` 源码。没有启动模型、读取密钥、改宿主配置、安装插件或做真实桌面运行验收。
- 本机宿主与 SDK 基线：DeepSeek Harness `0.2.0-rc.2`；示例插件源码版本 `0.7.8`。本机安装包确实含有下面引用的能力包，不能因本项目暂未实现，就推定宿主没有相关能力。

## 1. 结论与证据等级

**主要 UI 扩展点和基础执行能力已经存在。**左侧入口、B 区主页面、右侧栏 Tab、自定义 `@` 来源、结构化引用、模型能力查询、工具分发和领域持久化均有本机官方 SDK 证据。宿主甚至已有脚本型动态工作流引擎，应先评估复用。

**现有引擎不等于本 PRD 的完整运行器。**官方明确说明其没有已保存工作流、检查点恢复等能力；公开启动请求必须提供存活的父 Agent，没有可热更新运行图的公开方法。完整画布执行、独立运行、版本化修改和节点恢复仍需本插件补齐。

本文使用三个判断：

- **存在**：官方文档或类型明确给出扩展点／能力；仍需本插件实现和真实验收，不能理解为产品已经可用。
- **需要宿主扩展**：只有在现有扩展点不能满足严格交互，且必须复用原生路径时才采用；不把“插件需要写代码”混同于“必须改宿主核心”。
- **未证实**：明确说明缺少哪条证据及验证办法；不将未检查到当作不存在。

源码／声明检查是静态证据。SDK 存在、实际服务已挂载、插件成功调用、桌面交互验收分别是不同层级，当前完成第一层。

## 4. 推荐技术分层

```text
A 导航入口 ──→ WorkflowMain（主页 / B 区画布）
对话引用 ───→ WorkflowSidebar（同一流程的侧栏画布）
                   │ 共享插件状态，切换视图不新建运行
                   ▼
Client：画布、选择/注释草稿、@来源、设置、运行与询问 UI
                   │ 经过宿主 Gateway / Typert Remote
                   ▼
Host：工作流库、图校验、权限校验、版本提交、图运行器、运行日志
                   ├─ 确定性节点适配器（条件/数据变换/文件等）
                   ├─ ctx.llm（模型节点）
                   ├─ ctx.tools（授权内工具执行）
                   └─ Agent / workflowEngine 适配器（适合的子任务）
```

- 生成 Agent 和手动编辑都输出同一种可校验图定义；先提交有效版本，再让运行器执行。Agent 不拥有绕过图、固定节点或执行权限的特殊后门。
- **图定义是权威对象。**不要尝试把任意 JavaScript 脚本可靠地反编译成可编辑画布。可采用图编译到受控执行计划，或 Agent 按图变更协议输出结构化修改。
- `workflowEngine` 现有能力优先复用，但其脚本运行必须有父 Agent，且无运行中 patch／检查点。是否复用为 Agent 子流程后端，由最小样例验证；不能把全部 Dify 节点硬编码进一次不可调整的脚本后，仍宣称支持逐节点动态改图。
- 角色提示词与模型、工具、思考强度分别存储；宿主完整 Agent preset 只作为可选技术配置来源，不冒充用户定义的“角色预设”。
- 注册与订阅采用 Cordis lifecycle disposer；卸载时取消本插件持有的执行并等待清理，不停止其他插件任务。示例 AGENTS 与 S05/S24 提供惯例，不能直接复用其私有数据目录。

## 5. 本插件拟定数据与执行契约

**本节所有名称都是待实现的设计契约，不是宿主已有 API。**传输可通过 Typert Remote 实现，但 schema、权限与状态机归本插件。

### 5.1 数据对象

| 对象 | 最小字段与约束 |
| --- | --- |
| Workflow | `workflowId, workspaceId, title, schemaVersion, draftRevision, nodes, edges, viewport, notes`；工作流身份不随改名变化 |
| Node | `nodeId, displayNumber, kind, inputBindings, outputSchema, config, fixedPolicy, rolePresetId`；稳定 nodeId 与可变编号分离 |
| WorkflowRevision | `revisionId, workflowId, parentRevision, graphHash, actor, reason, createdAt, changeBatchId`；历史不可原地改写 |
| Run | `runId, workflowId, sourceRevisionId, effectiveRevisionId, inputs, authorizationSnapshot, configSnapshot, status`；本次变化不直接覆盖原流程 |
| NodeExecution | `executionId, runId, nodeId, iteration, attempt, inputHash, resolvedConfig, status, resultRef, sideEffectReceipt`；循环与重试必须可区分 |
| ChangeBatch | `batchId, baseRevision, operations, touchedNodes, authorization, validation`；一次 Agent 修改／整组撤销单位 |
| Question | `questionId, runId, nodeExecutionId?, fields, status, answerRevision`；独立运行也可发起，不以主聊天 Session 作为必需主键 |
| AnnotationDraft | `batchId, annotationId, sessionId, workflowId, nodeIds, graphRevision, text, submitState`；临时序号仅属于当前草稿 |
| RolePreset | `presetId, name, prompt, revision`；运行启动解析并快照，预设编辑不改写历史 |
| RunEvent | `runId, seq, eventType, nodeExecutionId?, effectiveRevisionId, time, payloadRef`；seq 单调递增，支持断线续读和去重 |

### 5.2 拟定操作

| 操作 | 输入／结果 | 必须保证 |
| --- | --- | --- |
| `workflow.list` / `get` | workspaceId、筛选、分页／流程与版本 | 工作区边界、稳定身份、无模型调用 |
| `workflow.saveDraft` | baseRevision、变更批次／新 revision | 乐观并发校验；冲突保留双方内容，不静默覆盖 |
| `workflow.validate` | revisionId／节点与连线诊断 | 结构、类型、依赖、固定约束、权限一起校验 |
| `run.start` | workflowId、revisionId、inputs、idempotencyKey／runId | 相同幂等键不重复启动；独立运行不要求主 Agent |
| `run.patch` | runId、baseEffectiveRevision、ChangeBatch／新运行版本 | 先检查状态、固定保护、授权与结果失效范围，再原子发布有效版本 |
| `run.control` | runId、pause/resume/cancel/retryNode | 清楚区分暂停调度与已启动调用取消；不虚报停止成功 |
| `run.answer` | questionId、answerRevision、answer／接收结果 | 回答幂等；过期、已取消、已回答请求不可重复恢复运行 |
| `run.events` | runId、afterSeq／快照及增量事件 | 断线可补读；不能以浏览器缓存作为运行真相 |
| `workflow.commitRun` | runId、原流程 baseRevision／更新或另存结果 | 用户显式选择；原流程已变更时报告冲突 |
| `annotation.stage` / `commit` | 草稿批次、稳定节点引用／聊天草稿引用 | commit 只进入输入框；最终宿主消息准入成功后清本批标号，失败保留 |

### 5.3 核心状态和约束

1. 未启动节点可以在授权内采用新有效版本；正在执行节点固定启动时配置，修改默认下次执行生效；明确停止重跑另走控制操作。
2. 完成结果按输入、配置及依赖版本判断能否复用；不能仅按节点名称或当前编号认定有效。
3. 两轮自动修复计数归同一故障身份，改名／替代节点不重置；达到上限仍失败即暂停。A 模式先批准变更批次，B 模式在授权内应用。
4. Host 接收消息与 Agent 执行完成分开。注释序列化没有提交成功效力；成功准入后清除本批临时标号，不恢复历史序号。
5. 写入外部系统等非幂等操作保存执行凭证；进程重启或超时后先核验，结果不明不能无判断重复。撤销图修改不回滚真实副作用。
6. 持久化提交成功后才向 Client 宣布版本已保存；跨多记录变更需实现自己的提交边界与恢复日志，不能假设底层领域存储自动提供事务。
7. 角色预设统一修改按用户授权影响新运行，包括引用它的固定节点；Agent 不得利用修改全局预设绕过固定保护。当前运行仍用旧快照。

## 8. 性能验收建议

**下表是待评审目标，不是本轮实测结果，也不是所有硬件的承诺。**先在 macOS 16 GB Apple Silicon 与 Windows 16 GB、4 核以上、SSD 的参考机上固定宿主版本、插件版本和数据集。冷／热启动分开；采集 30 次操作的 p50/p95。模型网络耗时与插件调度／渲染耗时分别报告。

| 场景 | 建议目标 | 测量边界 |
| --- | --- | --- |
| 管理页首屏 | 本地 1,000 条工作流元数据，热打开 p95 ≤ 500 ms | 点击 A 入口到首屏卡片可交互；缩略图延迟加载 |
| 常规图打开 | 200 节点／300 连线，p95 ≤ 1 s | 取得本地定义到画布可操作，不含模型生成 |
| 复杂图打开 | 1,000 节点／1,500 连线，p95 ≤ 3 s | 虚拟化／分层渲染策略必须说明；失败给出瓶颈 |
| 拖动／平移 | 200 节点场景交互帧间隔 p95 ≤ 33 ms | 连续操作 10 秒，采集帧分布；不以平均 FPS 掩盖停顿 |
| 自动保存反馈 | 普通变更停止输入后 1 s 内显示真实保存结果，持久写入 p95 ≤ 300 ms | 区分防抖等待与磁盘提交；失败必须可见 |
| @ 与工作区筛选 | 1,000 条元数据，热查询 p95 ≤ 200 ms | 输入到可选结果，检索失败不假装无结果 |
| 事件呈现 | Host 发出节点事件到 Client 显示 p95 ≤ 200 ms | 本机 Gateway；大输出分页／引用化，不逐 token 重绘整个图 |
| 内存稳定性 | 100 次打开／关闭 200 节点流程后，稳定堆相对基线增长 ≤ 50 MB | 停止执行并等待清理后采样，区分可回收与泄漏 |
| 取消反馈 | 操作后 ≤ 200 ms 显示“正在停止”，合作式模拟节点 ≤ 2 s 终止 | 真实外部工具取消能力单独验证；不能提前报告已停止 |
| 恢复正确性 | 100 组注入中断用例：0 次已确认保存丢失，0 次未知外部动作盲重放 | 强调正确性，不将跨进程存活误作必须不停机执行 |

上述容量用于测试基线，不是删减用户可创建节点数量的产品上限。达到瓶颈后应公布可支持规模及改进方案，再集中评审。
