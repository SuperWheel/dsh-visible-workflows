自动化覆盖的关键行为包括：

- 必填输入不足时等待，补齐后继续同次运行，重复提交被拒绝。
- 条件和分类只激活匹配出口；跳过的分支不执行；聚合保留合法的 false、0 和空串。
- 人工介入独立于运行前补参，支持无字段行动选择、变量预填、持久化等待、恢复和超时出口；恢复不重放已完成的模型或工具步骤。
- 迭代的顺序、并发上限、输入顺序、空数组，以及失败终止／保留 null／移除失败项；循环跨轮变量、条件结束、最大轮次和 Exit Loop。
- 退出循环在后续人工介入恢复时仍保持终止语义，不因读取成功记录而执行额外轮次。
- JavaScript 隔离执行、数据处理工具、HTTP 和文档适配器，以及无模型的跨模块执行链。
- 乐观版本、Agent 固定节点保护、包含固定节点的容器保护、全图 UUID 唯一性与递归编号。
- 取消传播、角色提示词快照、存储重开、运行中断状态与模型目录故障隔离。
- SDK 保留方法名契约，避免 Remote 名称覆盖宿主内部方法。

### 本轮宿主接入修复

发现并修复了 Cordis `agents` 服务依赖注入问题，同时消除了独立执行对“先初始化主对话 Agent”的依赖。代码、模板、容器、内置工具和 HTTP 等独立流程可以直接由运行按钮启动；调用宿主插件或 MCP 工具仍需有效的当前工作区对话权限，并经宿主工具管线执行。

此前 Remote 方法与宿主保留名称冲突的问题也有专门回归：删除接口使用 `deleteWorkflow`，避免覆盖 SDK 的内部 `remove`。这类接入问题说明仅完成 TypeScript 编译不足以证明插件在真实宿主中可用。

## 6 已知产品差异

- 当前 Agent 是有轮数上限的 JSON 决策与真实工具调用，未实现 Dify New Agent 的独立环境和完整能力管理。真实模型调用仍未验收。
- 知识检索为本地文档关键词检索，未实现向量知识库、重排模型和多模态检索。
- 模板使用受限 Jinja 数据语法子集；Python 为受限纯数据语法且要求宿主完整文件沙箱。未提供任意代码包、网络和文件访问。
- 文档提取只覆盖已实现的格式，不具备全部 Office 结构恢复、OCR 或音视频转录。HTTP 目前是文本请求与响应，尚未完整实现二进制、multipart、认证管理和全部节点重试／错误策略。
- 变量赋值作用于本次运行或循环局部变量，不跨聊天会话保存。含人工介入的迭代使用顺序模式；含人工介入的流程当前不能作为子工作流工具调用。人工介入外部交付渠道未实现。
- 运行中图修改、运行版本合并回原流程、Agent 自动修复两轮与可信的一次固定节点授权未实现。当前运行或等待时阻止改写原流程。
- 自动触发、发布、完整 DSL 往返、多人协作与完整 Dify 插件生态适配仍未完成。完整对标目标保持在 PRD 中，不能因本轮范围而删除。

## 7 复现与验收入口

```sh
npm run build

npm test
```

完整构建后，在隔离官方 Harness Web 配置中加载插件，从 `http://127.0.0.1:5188` 进行验收；需要认证时使用宿主启动输出的访问链接，不将认证参数写入仓库。本机 HTTP 样例使用 `scripts/validation-http-server.mjs`，仅监听 `127.0.0.1:5191`。

`npm run preview` 默认地址为 `http://127.0.0.1:5187/src/preview/index.html`，仅用于单组件调试，不能作为宿主验收。该预览没有完整的宿主对话、权限与模型环境；不要占用官方 Harness Web 的 5188 端口。

打包应使用完整 build。`--host-only` 仅用于 Host 开发，不能在它清理生成目录后将不完整输出作为安装包交付。
