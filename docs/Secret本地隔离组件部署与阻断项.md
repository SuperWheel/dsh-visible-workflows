# Secret 本地隔离组件部署与阻断项

日期：2026-10-17。目标：在现有 DeepSeek Harness 插件中迭代，采用本地、免管理员、按需运行的凭据代理与执行隔离；保留原画布、节点批注和图标式环境变量/系统变量入口。

## 1. 本轮结论

当前只能交付 **组件部署、关闭式检查与接口验证**，尚不能安全开放 Secret。实际 Harness 的进程测试发现了脱离原进程组后仍存活的后台进程；全局工具入口、联网 CLI/MCP 与 Windows 的完整隔离也未完成验收。不能把执行器能启动、二进制哈希一致、或单元测试通过解释为主 Agent 和子 Agent 已无法读取凭据。

安装状态：**已于 2026-10-17 11:22（北京时间）安装到真实 Desktop 并重启验收；仅组件部署，Secret 与全局隔离仍关闭。**

本轮没有录入、读取或发送真实 API 密钥，没有触发生物认证或真实模型调用。不改变现有公共文件、子进程和 MCP 提供方；普通工作流继续走原有执行通路。Secret 在用户界面、运行预检和受控调用三处保持不可用。

## 2. 已完成的组件

| 组件 | 当前实现 | 能说明什么 | 不能说明什么 |
| --- | --- | --- | --- |
| MXC 最小分发 | 固定 1.0.1 Mac ARM64 执行器及许可、上游 SPDX；执行前校验版本、大小、哈希和权限 | 已校验执行器可建立受限进程 | 不是全局工具隔离；Windows 未启用 |
| 私有隔离门槛 | 内存对象身份、16 项实际检查入口、短期操作摘要许可、撤销和到期 | JSON、画布配置和自报 ready 不能变成许可 | 检查器不能注册固定 true；本次安装的门槛明确关闭 |
| 文件访问适配 | 固定且校验过的 worker 在 MXC 中调用已安装的 fs-local | 文件效果可在沙箱中执行，越界/只读/工作区边界可实际测试 | 尚未替换全部 Host 文件入口；watch 等入口需独立支持 |
| 子进程适配 | 对接真实 Harness spawn、stdin/stdout、控制通道和退出契约 | 可以复用宿主接口，避免另造运行环境 | 尚不能完整清理脱离进程组的后代；PTY 尚未启用 |
| MCP stdio 适配 | 使用 Host 受限进程接口，严格 JSON-RPC 分帧，丢弃诊断内容 | 与已安装 MCP Client 的本地协议交互通过 | 联网 MCP、HTTP MCP、启动与回调全部接管尚未完成 |
| 本地凭据代理 | macOS 原生按需进程、固定操作、私有 FD3、原生录入和生物认证代码 | 不把原值放入插件 JSON、环境变量或 Agent 返回值 | 未执行真实凭据验收；FD3 和 ad-hoc 签名本身不构成对同用户程序的隔离 |
| 代理完整性检查 | 构建时记录包内全部运行文件清单，清单哈希编入 Host；运行前验证集合、哈希和路径 | 发现缺失、篡改、多余文件和符号链接 | 仍需全局策略保护安装目录及依赖，避免检查后被替换 |
| 画布状态报告 | schema v3 仅包含闭合状态，不传路径、错误正文或凭据 | 明确区分组件安装与安全启用；禁止伪造 available | 报告本身不是授权 |

实现入口：`src/host/isolation/`、`host-extensions/dsh-secret-isolation/`、`native/local-secret-broker/`、`native/mxc/`。全局 Host 扩展随包提供，但本次不在 Cordis 配置中启用。

## 3. 真实运行时验证

本轮使用 `/Applications/DeepSeek Harness.app` 自带 Node 24.18.1、Electron 44.0.0，以及实际安装的 rc.2 `subprocess-local`、`fs-local`、MCP Client；运行固定的合成探针，不建立另一套 Harness。探针与正在运行的桌面主 Agent 验收分开记录。

| 项目 | 结果与边界 |
| --- | --- |
| 文件 worker | 实际读写、版本 guard、只读拒写、越界符号链接拒读、直接保护路径拒读、多工作区、字节/流/stat/list 均通过；使用真实 FsError |
| MCP 本地 stdio | initialize、tools/list、tools/call 通过；仅固定合成服务，网络默认拒绝 |
| 控制 FD7 | 原始通道可通信；真实 helper 还要求 Host 在受限内层固定设置 `DSH_SUBPROCESS_CONTROL=pipe`，不能由 Agent 任意提供环境变量 |
| 普通进程 | `timeout=0`、由 Host 管理生命周期时，普通后代取消可通过；内层有限 timeout 会破坏原有进程组假设 |
| 交互终端 | MXC 内层有限 timeout 可使任务因 SIGTTIN 暂停；timeout=0 的输入、缩放和 EOF 可通过 |
| CLI 终端桥接 | 把整个 bridge 放进 MXC 会让 Electron 原始诊断混入严格 JSON 帧并失败；可信外层 bridge + 固定受限子目标的合成验证通过，尚未接管真实 CLI |
| 脱离进程组 | 父进程退出后，setsid 后代可重挂到 PID 1；Host 报告退出仍可能有后代存活。阻断完整启用 |
| Windows | 没有 Windows 实机验收；返回不可用，不做 DACL mutation、管理员 host-prep 或不受限回退 |

原始结果位于 [本轮证据目录](evidence/secret-local-deployment-2026-10-17/)。失败结果同样保留；所有合成残留进程都由探针清理，不把清理动作算作产品生命周期能力。

## 4. 轻量化代价

当前 Mac 仅分发一个约 3.76 MiB 的 MXC 执行器，原生代理运行包约 236 KiB；另有 SPDX、许可、worker 和 Host 适配代码。没有 Docker、VM、WSL、FFI SDK、独立 Node 运行时或常驻本地 HTTP 服务。完整插件包还含原有 Graphon 运行时，其体积不能计为新增隔离服务成本。

原生代理仅在获得有效门槛许可后按需启动；本次门槛关闭，因此不会启动凭据 UI 或驻留代理。文件 worker 的每次启动存在延迟，不能把 `/usr/bin/true` 的 MXC 额外约 10ms 当作实际文件访问延迟；实际 16 字节文件单次 readText（已 resolve，包含完整性检查、探针和 worker；2 次预热、10 次样本）中位数 93.43ms，P95 104.84ms；resolve 还需额外一次 worker，因此此实现尚不适合大量细碎文件访问。后续若采用受控复用 worker，必须同时解决权限隔离、工作区切换、撤销与存活范围，不能为了速度复用未受控后台进程。

## 5. 后续启用前的必要工作

1. 在真实 Host 启动层建立顺序屏障。Cordis 同层配置并行激活，不能依赖 YAML 行顺序；私有原始提供方不得被 Agent 或其他消费者获取。
2. 对全部主/子 Agent、文件/搜索、shell/PTC、CLI、MCP 启动与回调、工作流直接文件/网络/Python 访问实施同一策略；现有后台进程必须确认退出。
3. 解决后台新会话、父进程先退出、Host 崩溃、强制取消和 PID 重用等生命周期问题。`waitForExit:true` 不能代替真实后代清空证据。
4. 为 CLI/MCP 制定可保留正常联网能力的受控远端策略，验证终端桥接和控制 FD7；默认拒网的本地探针不代表完整 CLI 兼容。
5. 防止修改插件、依赖、配置及其真实链接目标，限制 GUI/AX、IPC、调试、信号等绕过入口。包更新必须撤销旧许可。
6. 完成 Windows 原生隔离、进程 Job Object、凭据存储和相同接口的实机验证，保持无管理员和失败关闭。
7. 以上全部通过后，再由用户在原生界面自行录入合成凭据，验证主/子 Agent 均无法读取原值及受控使用、撤销、重启。不可要求用户先把密钥发给 Agent。
