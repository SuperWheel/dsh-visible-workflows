# 恢复预览与运行详情样式验收

日期：2026-10-19。对应用户两张菜单截图及随后补充的按钮底部阴影要求。最终构建为 template5，插件版本仍为 0.0.2，已更新到官方 Desktop。

## 1、界面调整

依据《设计文档》2.1 和 DESIGN.md 第 4、10、11、15 节。后续章节覆盖早期冲突规格；本次修改限定在恢复预览和运行治理区域。

| 区域 | 最终实现 |
| --- | --- |
| 节点恢复计划 | 带标题、节点数量和边框的统一外框；内部卡片独立滚动，保持 12px 内边距与卡片间距 |
| 核验表单 | 标题及字段 13/20，辅助文字 12/18，字段组间 16px、标签与控件间 8px；清除原有重复外边距 |
| 处理决定 | 样式跟随宿主的原生 select，高 32px、圆角 8px，默认“尚未决定”；禁止选择的 completed 选项不展示 |
| 核验操作 | “检查核验决定”和“重新核验”同一行，32px 高，使用宿主 outline Button；结果显示待核验、核验中、核验通过或核验未通过 |
| 运行详情 | 来源、修订、账本与操作分组；清除账本默认外边距及成功状态的空操作区；恢复入口改为有边框的 32px 按钮 |
| 按钮阴影 | 检查、重新核验、取消、确认及创建恢复运行统一使用现有 `--vdw-floating-shadow`，保留边框、焦点与禁用状态。Modal 底部保留宿主标准 36px/14px 规格 |
| 输入错误 | 空白或超长说明、无效 JSON、非对象输出提供中文提示；有效输入仍提交 Host 检查，前端不会自行宣布业务执行成功 |

上表数字为实现规格，未将截图观察冒充浏览器 computed-style 测量。原生 select 的展开列表由当前系统绘制；控件本体沿用插件主题变量，未修改共享 Select 或其他插件菜单。

## 2、自动验证与桌面验收

定向组件测试 **28/28 通过**，构建与类型检查通过。覆盖空决定、说明/输出错误、Host 拒绝、处理决定条件、核验状态、编辑后失效、重新核验、重复点击锁、过期响应隔离及最新计划摘要提交。

| Desktop 实测 | 结果 |
| --- | --- |
| 成功与失败运行详情 | 账本与节点列表间距正常；失败恢复入口边框与轻底部阴影可见 |
| 恢复预览分组 | 外框、内部卡片、表单、按钮行和固定底部操作区可见且可滚动 |
| 下拉选择 | 实际点击展开并选择“允许重做”；重新核验后用方向键与回车选择成功 |
| 空说明 | 显示“核验未通过”和“请填写回执或核验说明。”，确认创建保持禁用 |
| 有效说明 | 实际 Host 计划检查通过，界面显示“核验通过”，确认按钮启用 |
| 修改已核验说明 | 立即返回“待核验”，确认创建重新禁用 |
| 重新核验 | 清空旧决定与说明，重新读取源计划，确认仍禁用 |
| 取消 | 点击取消退出弹窗；本次未提交恢复运行，未调用模型或执行文件写入 |

本轮是 UI 与预览交互验收，未重复执行上一轮已完成的业务流程。第三构建的 1,900 项全量回归及五节点业务恢复验收保留独立归属；本轮没有将其计为重新执行的测试，也未重新验证创建确认按钮的鼠标执行链。
