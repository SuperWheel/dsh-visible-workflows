# 工作流范围、原生引用与需求草稿验收

日期：2026-10-18。设计基线：[DESIGN.md 第 26 节](../DESIGN.md)。覆盖本轮注释操作、@工作流、需求菜单回编、全局设置和用户补充的自动保存报错。

## 实现

- 单行注释在蓝色发送箭头之前加入删除，支持新草稿与已有注释；移除独立关闭按钮，外部点击和 Escape 收起。折行测量计入删除按钮宽度，多行仍使用原左下删除、右下取消和蓝色保存。
- 工作流新增可保存的 `scope: workspace | global`，旧流程省略时按 workspace。画布管理菜单提供使用范围；首页卡片菜单、右键菜单第一项为“管理工作流”，打开独立居中弹窗。全局定义保留所属工作区，Agent 和规划器不能改变使用范围。
- 原生聊天 @ 仅列出本项目和显式全局流程，排除归档与其他项目私有流程。候选身份和引用载荷使用真实 ID，同名标题不会混淆；点击引用定位工作流，发送时重新读取范围与归属。
- 全局调用使用调用方项目的文件、工具、Secret 和会话权限，不继承所属项目授权；全局子流程也单独核验可见性。导入、复制和模板创建的新副本默认回到当前工作区范围，覆盖已有流程则保留目标范围。
- “交给 Agent”使用独立统一菜单，目标以 @名称呈现，正文只输入用户需求。聊天框只放置简洁的原生需求引用，显示目标和需求摘要；编号、规划 JSON 与协议指令在发送时解析。需求全文保留在编辑菜单与序列化载荷中。
- 同一会话、同一目标的重复提交替换原需求引用，不清空整个聊天框，不改旁边正文、其他引用或附件。重开保留本轮输入；失败、取消和乐观清空不消费需求。只有对应真人消息准入且需求 ID、版本匹配后重置；旧回执不清掉新修订。
- 恢复本地需求不会自行弹出菜单，点击“交给 Agent”才打开。新建工作流需求保留独立的预留流程 ID；保存后只跟踪该目标。

## 草稿保存报错修复

用户截图中的“草稿含有不支持的字段”来自本轮客户端新增 `generateRequestId`，但 Host `WorkflowEditorState` 的 payload 白名单漏同步。宿主拒绝自动保存，所以页面保留本地内容并提示错误；不是需求被发送或丢失。

现已加入该字段并验证为有界安全 ID，同时保留原字段白名单、Secret 限制和版本 CAS。新增测试使用真实 `WorkflowEditorState` 保存并重读客户端需求身份，同时拒绝对象等非法值。重启独立验收服务后，真实网页再次提交、等待自动保存和刷新重开均无该错误，最新需求完整恢复。
