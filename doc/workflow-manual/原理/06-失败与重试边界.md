# 失败与重试边界

> 核对日期：2026-10-21。依据当前源码及已有测试定义更新；本次文档整理没有重新运行这些测试，也不代表真实模型或安装端验收。返回[总索引](../README.md)。

当前已实现 Agent 输出修复、恢复计划和暂停后的运行修订。它们分别处理不同对象，不能合称为“任意节点失败后自动重试”。通用的逐节点重试策略、默认输出和失败分支仍未提供。

## 三类修复与恢复

| 能力 | 处理对象 | 当前行为 |
|---|---|---|
| 规划候选修正 | 尚未执行的 Workflow 图 | 初次候选加最多两次修正，处理字段、引用、结构等诊断 |
| 业务 Agent 输出修复 | 已完成 Agent 动作产生的不合格输出 | 以无业务工具的新任务修正输出，每节点累计最多两次；不重放原动作 |
| 业务运行恢复 | 已结束运行的快照与执行记录 | 先计算可复用、须重做、被阻断的实例，再创建关联原记录的新运行 |

规划修正属于[规划引擎校验](../规划引擎/04-候选校验与有限修正.md)，使用独立的[规划资源保护与并发限制](../规划引擎/07-资源保护与并发.md)。业务输出修复的实际 Token 用量归集到所属业务根运行，两类修复的次数上限不互相替代。

## 普通错误怎样传播

| 触发点 | 实际行为 |
|---|---|
| 图结构或必需配置不合法 | 启动前校验失败，不提交执行 |
| 普通节点抛出错误 | Graphon 收到节点失败，宿主保存错误及已完成结果 |
| 迭代某一项失败 | 按 `terminate` / `null` / `remove` 处理；不是重试 |
| 参数提取返回不合格 JSON 或类型 | 返回 `__is_success: 0`、`__reason`，可由下游条件处理 |
| 分类模型返回未知类别 | 明确失败，不任意替换分类 |
| 人工等待超时 | 有 timeout 出口则走超时路径，否则失败 |
| Graphon 引擎异常退出 | 取消在途回调并保存失败；后续运行可重新启动引擎 |

部分文本、意外断流、截断输出或未完成的 Agent 动作不能伪装成成功。动作本身失败不进入“已完成输出修复”循环。

## Agent 输出修复的授权与停止条件

`native-agent` 仅在原任务 `completed` 后，对结构化输出或最低文本长度校验失败创建修复任务。先关闭原任务并归集用量，再把原输出及诊断交给新任务；该任务不获得业务动作工具。

- 默认要求确认。自动修复必须有 Host 记录的 `agent-tool` 或 `user-diagnostics` 授权来源，且根运行和当前图的策略允许自动模式；仅在 JSON 中写 `repairMode: auto` 不够。
- 每节点总上限取根图、当前图的 `maxRepairAttempts` 与 2 的最小值。自动修复和用户逐次确认共享同一份修复轮次账本，失败、取消或再次确认不会重置计数。
- 修复使用同一根运行的模型并发上限；修复轮次上限耗尽、修复被关闭、适配器不可用或需要确认时，记录待验证输出并暂停。
- `confirmRepairOutput` 只授权一次输出修复，校验当前已用轮次，结束后保持暂停；下游动作须另行继续。
- `acceptRepairOutput` 接受人工提供的输出，仍检查结构、长度及已配置的文件证据；不能用人工 JSON 绕过证据要求。

存在待处理输出时，普通 `resume` 会拒绝继续。人工修正成功后，独立根运行且无其他待修复输出可自动进入继续；嵌套子运行仍留在暂停状态，由根运行恢复。以上路径都保留原动作身份，避免再次发送已经完成的外部操作。

## 失败运行怎样恢复

`recoveryPlan` / `recover` 已提供恢复入口。暂停中的活动运行使用 `resume`；失败、取消或中断等已结束运行的恢复会创建新运行，并用 `sourceRunId` 关联历史，不覆盖原运行。

恢复计划按执行实例列出 `reuse`、`rerun`、`blocked` 及原因：

1. 比较图语义、有效模型与角色、工具契约、输入、环境及上下游依赖。
2. 仅复用具有合法成功结果且满足缓存条件的实例；容器按具体项或轮次分析，不把整个容器结果无条件套回。
3. 将输入、配置或上游变化传播到受影响的下游；时间、文件等动态依赖可能使结果失效。
4. 已启动但结果不明的外部动作，以及需要重放的已完成外部动作，先阻断，交由显式核验或明确重跑处理。

`recover(..., 'resume')` 只复用计划许可的结果；`recover(..., 'rerun')` 明确按快照重新执行，不承诺保留成功步骤。外部核验可以记录“确认重做”或经校验的完成结果，但用户声明不等于独立核验通过，也不能绕过已变化的上下文或文件证据。

## 暂停后可建立本次运行修订

当前 `previewRunRevision` / `applyRunRevision` 已支持：在根运行完全暂停、在途任务排空、待验证输出及活动子流程已处理后，预览改图差异和缓存失效范围，再以匹配的 `planDigest` 应用。

应用时保留旧图及执行记录，递增 `activeRevision`，保留累计用量记录，只携带计划许可的成功缓存，并保持暂停等待显式继续。每次运行最多 20 次修订；不能借修订改变工作流归属、绕过固定节点或更改已有输入。

这与保存原工作流草稿是不同路径。当前存储允许按版本校验保存库定义，但不会因此改写已经冻结的运行图；运行修订也不等于已自动改写库中的原流程。版本与历史对象见[运行记录与版本](08-运行记录与版本.md)。

## 仍然没有的通用能力

| 预期能力 | 当前缺口 |
|---|---|
| 每节点重试次数、退避间隔 | 节点 schema 没有通用 retry 配置，运行器没有覆盖所有节点的 retry 循环 |
| Code / HTTP / Tool / LLM 通用失败出口 | 未统一定义失败端口与对应路由策略 |
| 任意错误的默认输出 | 未提供统一的失败默认值 schema 和执行策略 |
| 无需核验的外部动作自动重放 | 恢复计划会阻断结果不明或不可安全复用的动作 |

Graphon 当前接收自定义 `BridgeNode` 和图结构。权限、资源保护上限、尝试身份、输出验证、缓存失效及外部动作归属都由宿主管理，不能通过开启引擎重试选项绕过这些约束。
