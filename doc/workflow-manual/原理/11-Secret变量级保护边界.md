# Secret 变量级保护边界

日期：2026-10-17。状态：**macOS 已在真实 DSH 0.2.1-rc.1 接入系统 Keychain 和持久授权。用户一次保存并授权后，两次固定请求均无需再次认证，只返回假值预期的 HTTP 401；真实 JSON 往返保留画布结构，副本不继承值或授权。新包未重复人工撤销、修改、删除或重启；Windows 为未编译、未启用的源码候选。** 详见[本轮分阶段验收](../验证/10-DSH021适配与Secret管理请求验收.md)。前轮主/原生子 Agent 读取声明与逐次授权 CRUD 作为历史证据保留，不声称本包重新跑过模型。schema 4 只描述系统凭据组件和工作流接口边界；旧全局接管源码与产物已归档移除，历史结论见[实验及恢复记录](../验证/08-早期接管与严格Node隔离验收.md)。现有画布、节点批注和导入导出继续保留。

## 1. 用户已经明确的三个约束

| 对象 | 必须保留的行为 |
| --- | --- |
| Agent | 可以识别变量声明、选择 Secret 引用并编排受控节点；不能通过工作流接口读取 Secret 原值 |
| 用户 | 可以正常查看、写入、编辑和删除自己的 Secret；默认遮罩不能变成禁止用户查看 |
| DSH 与其他插件 | 保留原有配置、工具、CLI Worker、会话、普通变量和插件能力，不为一个工作流变量接管全局启动树、禁用服务或改造其他插件 |

原有环境变量和系统变量按钮继续只显示图标，悬停说明；可视化画布、节点位置、便签、节点批注、右侧待处理清单，以及点击执行后提示缺失配置的行为保持不变。

## 2. 系统凭据库与保证范围

用户最新选择使用 macOS 和 Windows 自带的凭据能力。这里采用 **macOS Keychain / Windows Credential Manager**，不是把 Secret 写成普通系统环境变量；系统环境变量可能被进程继承或枚举，不适合作为这项功能的存储方式。

保护范围是本插件提供的工作流数据、Agent 工具、变量解析、运行记录、快照及受控执行接口。工作流将 Secret 明文交给模型、模板、代码、输出或普通工具参数，均属于需要阻断的问题。

这与“阻止同一系统用户下任意原生插件、命令、调试器或已获授权的界面自动化读取用户本机信息”不是同一保证。保留这些能力时，不能仅凭系统凭据库、字段过滤或一个 opaque ID 宣称 OS 级全面隔离；用户主动显示的值也不承诺对所有屏幕读取能力不可见。不会为实现本功能限制 DSH 或其他插件。

| 平台 | 存储方向 | 认证及验收边界 |
| --- | --- | --- |
| macOS | 默认／登录 Keychain 的独立 service，由独立原生管理窗口录入、显示、编辑与删除 | 管理窗口使用 `deviceOwnerAuthentication` 做一次本人认证，窗口内保存与授权复用；授权后固定请求不再逐次认证。一次授权与两次使用已实机验证，账户密码回退和新包其他生命周期路径未重复人工验证；probe 不代替业务验收 |
| Windows | Credential Manager，由对应原生管理窗口管理 | Credential Manager 存储不等于 Windows Hello 认证；如需 Hello，必须单独设计和验证。目前 Windows 实机尚未验证，不宣称已可用 |

Windows 的独立候选、构建方式和逐项未验收清单见 [Windows OS Secret 组件说明](../../../native/os-secret-broker/windows/README.md)。当前仅完成源码和静态发布/输出面检查，未在 Windows 编译或验证原生窗口、Hello、Credential Manager 与真实 Agent；这些检查不用于打开 Windows 可用状态。

当前方案不复用旧全局通过结果；旧 gate 与实验入口已清理。OS 后端通过自身平台、完整性和接口检查启用，组件 ready、变量已配置与已授权分别报告。

## 3. 当前可直接保留的基础

| 已有实现 | 在新方案中的处理 |
| --- | --- |
| `EnvironmentVariable` 的 Secret 分支禁止 `value`，schema 使用严格字段校验 | 保留。Secret 值管理请求与工作流定义是两种不同数据类型 |
| JSON/ZIP 仅导出 Secret 声明；普通值是否导出由既有选项控制 | 保留；不得新增“导出密钥”选项或在附件中附带凭据存储 |
| 导入为流程、节点、变量、批注等生成新身份，并改写 Secret 操作引用 | 保留；复制、覆盖导入也不能继承原流程或目标旧流程的凭据绑定 |
| `environmentSnapshot()` 排除 Secret；通用解析器不提供 Secret 原值 | 保留；不能为了支持引用把 Secret 放进普通 `env` 字典 |
| HTTP `credentialOperation` 只保存变量 ID 和操作 ID | 可作为最小接入点；引用本身不授予读取值或任意发送凭据的权限 |
| readiness 查询值是否 configured/missing 及授权是否 authorized/required，失败显示暂不可用 | 保留无值状态查询，区分缺值与缺少自动使用授权；没有配置仍可保存 |

## 4. 已接入的最小接口

当前 Host 使用 `OSSecretBroker`，客户端通过 schema 4 读取状态与打开独立管理窗口。明文不进入 Host 返回类型。状态报告的 `available:true` 仅表示本组件通过启动检查，既不是某个变量已配置的证明，也不是本次使用授权。

| 接口 | 调用方与返回值 | 约束 |
| --- | --- | --- |
| 变量定义及 `SecretRef` | 用户编辑器、Agent 工具、导入导出；返回名称、类型、说明、稳定变量 ID、操作引用等元数据 | `SecretRef` 可沿用当前 `secretVariableId`，不提供转成明文的方法；猜到 ID 也不等于取得权限 |
| Secret 状态 | 编辑器/readiness；返回 `configured/missing` 与 `authorized/required`，调用失败对应暂不可用 | macOS 查询值存在/epoch 属性及非密钥授权记录，不读凭据 value、不弹认证；导入文件不能声明本机已配置/已授权，也不向 Host 返回 epoch |
| 用户值管理 | 打开独立原生窗口时一次本人认证，窗口内查看、编辑、粘贴与五个管理动作；协议返回 `saved/authorized/revoked/deleted/unchanged` 及授权状态，不返回值 | 不注册成 Agent 工具，不提供明文读取 RPC；`actor=user` 或公开 scope 不是可信身份。关闭未保存时不修改值 |
| 受控消费 | 运行器校验冻结定义的引用；原生核对当前 epoch、scope 与固定目标授权，通过后内部读取并发送，只返回 HTTP 状态码 | 后台不打开 UI、不进行系统认证；无授权返回 `authorization_required` 且不发送请求。原值和 epoch 不返回 Host；状态报告不是使用授权 |

原生窗口只有“仅保存”“保存并授权自动使用”“撤销自动使用”“删除”“关闭”五个动作。“仅保存”轮换 epoch 并撤销旧授权；“保存并授权”在同一已认证窗口保存并对明确显示的固定目标授权；撤销保留值，删除同时移除值与授权。授权保存在本机，持续到用户撤销；凭据或目标变化需要重新授权。撤销不能追回已经发出的请求。

存储身份绑定 `workspaceId + workflowId + variableId`，独立于变量名称和消费节点。重命名保留绑定；跨工作区、导入和复制不复用身份，覆盖导入也生成新变量 ID。原生存储内部用 epoch 对保存和删除进行比较，避免并发编辑直接覆盖；epoch 不返回 Host，不进入画布或快照。

**删除工作流中的声明不会自动删除 Keychain 项目。** 当前应先在原生管理窗口删除值，再删除声明；只删声明不会读取或删除凭据。自动清理孤立项目仍是待改进项，不能将“引用从画布删除”描述为系统凭据已经撤销。

值由独立原生组件与系统凭据库管理，不进入 `library.json`、编辑草稿、运行快照、事件、缓存键、导出包或 Agent 返回对象。Host 传递声明身份、管理请求和受控操作，不通过 stdin/stdout 或返回对象接收 Secret 明文。平台组件缺失或系统凭据库不可用时，该 Secret 功能明确不可用；不得回退为普通环境变量或明文 JSON 文件，也不能因此禁用 DSH 的其他功能。

用户在原生窗口内主动显示或编辑值，默认遮罩；正常粘贴保留，不做全局剪贴板限制，也不自动把密钥复制到剪贴板。网页面板只显示声明和配置状态。不得复用会自动保存的 `EnvironmentDraft.value`，不得把原生窗口中的值同步到客户端 store、浏览器持久存储、错误详情或聊天；窗口关闭后的清理也不宣称可证明的内存擦除。

## 5. 引用与后端注入

Agent 可在“凭据”类型的节点槽位选择引用，或修改节点中的声明性操作引用。Secret 不参与普通字符串插值：即使是 `{{env.<id>}}`，用于 prompt、模板、代码输入、输出节点、普通工具参数或普通 HTTP URL/body 时，也应返回明确的类型错误，不能替换成密钥或静默变成空字符串。

当前实现复用已有受控 HTTP 操作接口。Host 校验引用归属，原生核对固定目标、方法、认证位置以及当前有效的自动使用授权，在发送前注入密钥；运行记录仅保存操作 ID 和变量引用。当前仅提供 `deepseek.account-status.v1`，即 `GET https://api.deepseek.com/user/balance` 的状态检查，不返回余额或响应正文。这不是任意 API 插值器；扩展其他凭据用途时应另行定义操作或绑定规则。

原生存储支持 1–2048 UTF-8 字节、非 NUL 的通用密码，允许 Unicode、空格和标点。存储成功不代表该密码适用于 DeepSeek 的 Bearer 认证；固定消费器使用时另行校验 token 语法，不将通用密码随意拼进请求头。

不得允许 Agent 修改节点 URL 后，将同一 Secret 发到任意目标。受控目标及认证位置需由可信后端操作定义，或由用户管理的独立目标绑定确定；导入文件不能创建该授权。重定向不得携带凭据跳转到其他目标，错误和调试输出不能带请求头或原值。

受控响应也必须有明确输出契约。例如账户查询只返回允许的业务字段，不能向下游原样返回可能回显认证头的响应。简单按字符串替换密钥不能覆盖编码、截断或加工后的泄露，因此脱敏只作补充，不能代替受控目标和结果结构。普通无凭据 HTTP 节点保留原行为。

## 6. 导入导出、保存和运行的兼容

| 场景 | 目标行为 |
| --- | --- |
| JSON/ZIP 导出 | 保存完整图结构、位置、视口、便签、批注与 Secret 声明/操作引用；绝不包含 Secret 原值、本机存储路径、会话令牌或可迁移授权 |
| 导入/复制/覆盖 | 直接进入画布，Secret 保留名称和用途；生成目标身份并清除本机绑定，提示用户补值；不得与目标中同名旧变量自动绑定 |
| 未配置完成 | 正常保存；节点标题红色警告和右侧待处理列表继续定位问题；点击执行再弹缺失配置提示，不直接禁用按钮 |
| 可选且未使用的 Secret | 不因未设置值阻塞整张图；必需或被受控节点引用的 Secret 才进入必要配置检查 |
| 运行前与实际消费前 | 运行前查当前值/授权状态；实际消费再次核对本机授权与当前 epoch。状态检查不代替使用时检查，缺少有效授权不弹窗也不发送请求 |
| 暂停/续跑 | 快照只持有引用和普通环境值，不保存 Secret、epoch 或授权；后续消费核对当前值及其当前授权。保存新值撤销旧授权，重新授权后使用新值；不会恢复旧凭据，也不声称 Host 快照绑定了旧 epoch |
| 删除 | 在原生窗口删除值可保留声明及节点引用，使其回到待填写；删除声明按既有引用检查处理，但不会自动删除 Keychain 项目 |

当前新包已在真实 Desktop 导出、修改副本标题并导入新流程，3 个节点、2 条边、1 条便签、1 条批注以及位置、引用和视口完整保留；副本只带六个 Secret 声明字段，没有值或授权。执行按钮可点击，缺配置时弹出提示且没有创建运行。证据见[真实 JSON 往返](../验证/DSH021证据/persistent-json-roundtrip.json)。

## 7. 验证证据与限制

当前原生组件通过 10 组检查，含 74 项断言和 7 个确认退出的真实子进程；这组检查没有本人认证、Keychain 读写、UI 或网络。全量 96 文件/992 项测试中的两项 localhost 沙箱失败已在许可环境单独复跑解决；最终授权相关 5 文件/84 项通过，含导入伪造授权字段检查。测试数存在重叠，不相加，详情见[本轮验收](../验证/10-DSH021适配与Secret管理请求验收.md)。

| 验收面 | 当前结果与边界 |
| --- | --- |
| 用户管理 | 逐次授权版本已实机完成查看、编辑、重开持久化和删除；新持久授权包实际完成一次认证与“保存并授权自动使用”。新包未重复人工撤销、编辑后授权或删除 |
| 主/子 Agent 工作流接口 | 前轮真实主 Agent 与原生子 Agent 的流程读取只有声明、无原值，首轮错误和修复分别保留；本包未再次调用真实模型，接口拒绝由回归继续覆盖 |
| 受控 HTTP | 新包一次授权后，两次真实请求无再次认证，均只返回 `{ok:false,status_code:401}`；假值被目标拒绝，不能称为有效 API 密钥认证成功 |
| JSON 与缺失引导 | 新包真实往返保留结构，副本不继承值/授权，可保存、点击执行弹缺失提示且无 run；ZIP、覆盖和伪造字段由回归覆盖，本轮未另做实机 |
| 生命周期 | 撤销、凭据/目标变化失效、并发边界等有原生/集成回归；新包未重复人工撤销、修改、删除或重启，不将静态检查和模拟协议扩张为实机通过 |
| DSH 兼容 | 新包在真实 0.2.1-rc.1 加载，画布、便签、节点批注、变量图标与导入入口保留；原 8 份定义以 v6 基线核对不变，其他插件配置条目语义保持，不声称其他插件全功能逐项验收 |
| 平台 | macOS 本轮路径有实际证据；密码回退、完整 CAS/ACL 变化及 Windows 仍无完整实机结论，Windows 不启用 |

## 8. 当前交付状态

系统凭据、原生管理、固定目标持久授权及 JSON 迁移已接入现有插件，旧全局接管源码与包内资产已清理。原流程保留用户用于验收的假测试值和固定授权，导入副本无值、无授权、未执行。用户可以自行撤销、修改或删除；这些动作不需要 Agent 读取值。保护边界仍限于工作流接口和受控数据流，不承诺抵御同一账户下任意本机代码。当前安装包与分阶段证据见[DSH 0.2.1 验收](../验证/10-DSH021适配与Secret管理请求验收.md)，[前轮第 09 篇](../验证/09-系统凭据存储与真实Harness验收.md)保留历史结果。
