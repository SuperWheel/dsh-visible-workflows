# 暂停、恢复与停止

> 核对日期：2026-10-21。当前实现审计；返回[总索引](../README.md)。

人工等待的持久性来自宿主快照。Graphon 的暂停事件负责停止本层后续调度；暂停后不会把 Graphon 引擎帧持久化到磁盘。

## 两种等待

| 场景 | 等待时保存什么 | 提交后做什么 |
|---|---|---|
| 启动时缺少必填输入 | 图快照、已有输入、缺失字段 | 校验并补全输入，再启动顶层图 |
| 运行到人工节点 | 节点执行身份、已渲染提示词/字段默认值、操作按钮、等待起点、已成功步骤 | 将用户操作保存为该节点成功结果，重新提交图并使用成功缓存 |

人工节点即使没有字段也会等待用户选择操作；不会自动点击默认行动。回答只能提交给仍为 `waiting` 的运行。提交后状态立即变化，重复回答或超时后的旧回答会被拒绝。

## 恢复为什么不会重做前面的工具

1. Python 图收到 `control: pause`，发出 Graphon 暂停事件并结束本次图请求。
2. 宿主保存成功节点的 `data`、`selectedPort`，以及人工表单状态。
3. 用户回答后，宿主重新执行相同的运行快照。
4. Graphon 再次调度已成功节点时，宿主直接返回缓存，不再调用其模型或工具。
5. 赋值节点的缓存结果用于重建变量；容器进入原项/原轮路径以恢复进度。

恢复仍会经历调度 RPC，而不是从 Graphon 某个序列化 frame 继续。这种机制避免重复**已经记录为成功**的外部调用；不能保证进程崩溃前“外部已执行、成功结果尚未落盘”的动作可自动判断是否发生。

## 人工超时

默认等待 3 天，可配置 1 秒～30 天。宿主以保存的 `waitingSince` 重新计算剩余时长，重启后重新挂定时器。若有 `timeout` 出口，生成超时结果并只激活该出口；没有超时出口则使运行失败。

## 停止的责任链

```text
停止按钮 → runtime.cancel → AbortController
    → 取消宿主模型/工具回调
    → JSONL cancel → Graphon request_abort
    → 等待正在执行的任务结束 → 保存 cancelled
```

等待表单中的运行也可取消，清除定时器并标记未完成步骤。停止不会撤销已经写出的文件、已发出的 HTTP 请求或工具已完成的外部动作；画布撤销同样不是这些动作的回滚。

## 重启与故障的不同处理

- 人工等待：保留 `waiting`，可在重启后回答并恢复。
- 旧运行的 `budget_waiting`：只读兼容并显示为“旧运行已暂停”，可在宿主支持且满足恢复条件时继续或停止；新运行不产生该状态，不批量改写旧记录。
- 宿主在普通执行途中重启：改为 `interrupted`，明确提示未自动重放可能产生外部副作用的节点。
- Graphon 子进程异常退出：运行失败，在途宿主回调收到取消；迟到结果不得改写为成功。下一次新运行可以重新启动引擎。
