# 运行记录与版本

> 核对日期：2026-10-21；下文存量图及边界探测保留 2026-10-16 的历史证据，本次文档整理未重新执行这些运行。返回[总索引](../README.md)。

工作流草稿与某次运行是不同对象。Graphon 负责调度，插件自己的存储负责工作流版本、运行快照、历史记录及人工恢复。

## 启动时冻结什么

`WorkflowRun` 保存完整图 `graph`、`sourceRevision`、工作区、输入、角色提示词快照、默认模型快照和 `engine: {name: graphon, version: 0.7.0, protocol: 1}`。

节点有效模型/思考强度在启动时解析：缺省值复用 DSH 当前配置，显式节点选择保留；本次运行后续的循环、迭代与恢复继续沿用快照。运行中切换宿主模型或修改角色预设，不改写已启动请求的配置。

## 每个节点步骤记录什么

| 信息 | 用途 |
|---|---|
| 稳定 nodeId、显示编号/标题 | 关联到该次快照的节点 |
| executionId、父容器、iteration | 区分同一节点在各项/各轮的步骤 |
| pending/running/waiting/success/failed/skipped/cancelled | 展示真实状态与路径 |
| 输入、输出、结构化 data、selectedPort、error | 运行详情、后续取值、恢复缓存 |
| 开始/结束时间 | 计算步骤耗时 |
| model、effort、rolePrompt、tokenEstimate、tokenUsage | 显示该次有效配置、分词估算及已收到的真实用量 |

轻量分词只给 Token 估算。当前运行器接入提供方用量与原生 Agent 会话事件，将合法回执汇入节点 `tokenUsage` 和根运行用量记录，只作性能计量。运行详情展示“已报告实际用量”“未知用量调用”“待返回用量回执”和“调用 / Agent 任务”；缺失回执保持未知，不补零，估算不计入实际用量。规划任务单独记录用量，见[规划资源保护与并发](../规划引擎/07-资源保护与并发.md)。

当前运行记录通过 `usage` 归集用量，子工作流以 `rootRunId` 指向根运行。旧记录只有 `budget` / `budgetRootRunId` 时，读取时在内存中换成新名称，不改写文件；保存时过渡期同时写入这两个旧名称，只为回退到旧版本后仍能读取用量并协调子运行。旧 limit 和估计值可读但不参与执行限制。新调用不预留 Token，迟到的可信回执按调用身份幂等补记。旧状态 `budget_waiting` 仍可读取，界面显示“旧运行已暂停”，按暂停条件继续或停止；新运行不产生该状态，也不批量重写旧记录。

## 同名输出保留什么

当前宿主在第二个实际激活的同名根输出执行前拒绝冲突：不渲染/覆盖第二个输出，保留第一个 `run.outputs[outputName]` 值，将后一步及本次运行标为失败并给出重复名称说明。它不自动合并数组，也不把所有同名配置一律静态禁用：互斥分支只激活一个输出时允许同名；子层输出由容器收集，不写根结果字典。

人工暂停与恢复重建时，同一个已成功输出的缓存重放不算新增冲突。多个都会激活的根产物应使用不同名字，或先明确汇总后输出，不用支路先后表达优先级。新增[输出冲突回归](../../../tests/output-collision.test.ts)覆盖以上契约。

修复前真实 Graphon 探测中，两条同名输出支路曾都成功，最终只剩 `{"result":"second"}`。这条历史证据保留于[边界与存量流程证据](../验证/边界与存量流程证据.json)的 `duplicateOutputName`，构造见[边界探测脚本](../../../scripts/audit-graphon-boundaries.ts)；当前状态见[问题修复记录](../验证/问题/03-同名输出覆盖.md)。

## 保存与冲突规则

- 库数据写入私有 `library.json`，临时文件写入并 fsync 后原子替换。
- 单 Host 锁阻止两个宿主同时写同一库。
- 修改草稿使用 `expectedRevision` 乐观锁；过期版本不能覆盖新版本。
- 自动保存和手动保存均按真实定义变化递增版本；相同内容不新增版本，仅平移、缩放或子图浏览位置变化也不新增版本。节点布局、配置、连线、批注等定义编辑仍递增版本。2026-10-18 的修复及提案基线核对见[提案接受与保存版本](../规划引擎/08-发布提案与幂等.md#61-接受后的界面与自动保存版本)。
- 所有活动运行保留；已结束运行只保留最近 200 条。
- 当前库定义按 `expectedRevision` 保存，保存不会自动修改已冻结的运行图；有活动运行时禁止归档删除该流程。
- 根运行完全暂停并满足前置条件后，可通过 `previewRunRevision / applyRunRevision` 检查差异和缓存失效，再建立本次运行修订。保留旧图与执行记录、累计用量，应用后仍等待显式继续；它不自动更新库中的原流程，详见[修复与运行修订边界](06-失败与重试边界.md)。

规划引擎修改已有图时先形成提案，用户接受后才进入库定义保存；提案发布与本次运行修订是两条独立路径，见[规划发布与幂等](../规划引擎/08-发布提案与幂等.md)。

本轮对Web与桌面两份存量库做只读结构检查；9个中3个安全流程在临时存储副本中实际执行成功，6个按结构或外部依赖原因保留未执行。`libraries[].unchanged`均为`true`，不能称为所有用户原流程逐个执行成功。逐项范围见[存量流程核验](../验证/02-存量流程核验.md)，原始计数见[存量证据](../验证/边界与存量流程证据.json)。

## 固定节点与统一预设

固定保护是宿主规则，不是 Graphon 的节点属性：Agent 保存时禁止修改固定节点语义、删除、改接边或新增绕过路径，也递归保护包含固定子节点的容器。用户在画布中主动修改固定节点允许保存；仅移动位置不视为语义变更。

预设只保存角色提示词。普通模型节点引用预设，用户更新后影响未来新运行；2026-10-17 起 Agent 节点使用工作流内子 Agent 定义的角色快照，须在卡片点击“更新预设内容”才同步来源预设。已启动运行始终使用原快照。固定节点引用的子 Agent 定义也受 Agent 修改保护，用户主动编辑仍走原有画布保存路径。详情见[Agent 节点](../节点/agent-工具调用Agent.md)。
