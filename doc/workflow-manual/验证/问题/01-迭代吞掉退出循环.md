## 修复前的最小条件与观察

初次审计使用外层 loop 最大 3 轮 → 内层 iteration 只有 1 项 → 项内 exit_loop，记录如下；这是保留的历史结果，不代表修复后行为。

| iteration.errorMode | 正确控制意图 | 修复前 loop.iterations |
| --- | --- | --- |
| terminate | 第一次遇到退出即结束外层 loop | 1 |
| null | 项失败留空不应吞控制信号 | 3 |
| remove | 项失败移除不应吞控制信号 | 3 |

三种组合都能通过图校验。后两种曾显示成功却继续到最大轮数。原因为 iteration 单项 catch 没有单独重新抛出 `ExitLoop`，把控制信号记成了普通项错误；问题位于宿主适配层。

历史证据：[JSON probes.exitLoopInsideIteration_*](../边界与存量流程证据.json)、[复现脚本](../../../../scripts/audit-graphon-boundaries.ts)。

## 当前控制契约

- `ExitLoop` 与人工暂停、用户取消分别传播，不受 `terminate` / `null` / `remove` 的业务失败策略转换；退出不会变成空结果、移除项或 `errors` 条目。
- 信号穿过嵌套迭代，到最近一层 loop 被捕获；只退出该 loop，外层 loop 仍可继续。
- 并发迭代遇到退出信号会停止派发新项，取消未完成同伴并等待清理。其取消错误不能覆盖已收到的退出信号；未完成步骤不残留 running。
- 已完成的工具副作用不会回滚。人工暂停后的恢复、成功 exit_loop 缓存重放以及用户取消继续遵守各自语义。
