# Secret 隔离与导入导出兼容验收

日期：2026-10-17。对象：现有 DeepSeek Harness Desktop 0.2rc2 与 `dsh-visible-dynamic-workflows` v0.0.1。

[返回手册](../README.md) · [JSON 字段说明](../原理/10-JSON字段与导入导出.md) · [前次导入导出验收](05-JSON导入导出与待配置验收.md)

## 1. 结论与验收边界

本轮沿用现有画布、节点批注、变量入口及 JSON/ZIP 导入导出。**声明迁移与缺失配置拦截可以验证，真实凭据的录入、受控使用和 Agent 拒读尚未完成闭环，Secret 不能开放。**

仅在没有存入任何密钥时，让 Agent 返回“读不到”，不能证明隔离。要完成最终验收，必须先在可信原生窗口存入专用合成凭据，证明合法固定操作能使用它，再验证主 Agent、子 Agent、CLI/MCP、文件/Keychain/IPC/界面自动化均无法取得原值；实际凭据不发给 Agent。

## 2. JSON 与 ZIP 兼容检查

| 场景 | 当前规则 | 验证方式 |
| --- | --- | --- |
| Secret 导出 | 仅保存名称、类型、说明、必填、稳定声明 ID、revision 等公开声明元数据；无值、句柄、授权、已配置状态；导入后 revision 归零 | JSON/ZIP 回归 |
| 包含普通变量值 | 只影响 String/Number；不会把 Secret 加入普通值快照 | 参数化回归 |
| 导入新流程、覆盖已有流程 | Secret 声明重建身份，受控节点引用同步更新；不复用源流程或被覆盖流程的凭据作用域 | 存储及预检回归 |
| 包内子流程 | 每个流程各自重建凭据作用域，父流程凭据不替子流程解除缺失状态 | 子流程回归 |
| 缺失配置 | 可以进入画布并保存；运行前检查阻断；目标端独立配置后才可解除 | 状态契约回归；桌面结果见后文 |
| 伪造值或授权 | Secret 的 value、binding、ciphertext、state、approved 等字段拒绝 | JSON/ZIP 非法输入回归 |
| 伪造消费方式 | 受控操作不接受任意 URL、Header、请求体；Secret 不允许普通模板插值 | 节点校验回归 |
| 布局与附件 | 坐标、便签、批注、视口和公开附件同时保留 | 实际 ZIP 文件往返回归 |
| 旧文件授权 | 所有导入均清理本机附件句柄与内嵌文件字节，不能因包内没有文件节点而跳过 | 本轮修复及回归 |
| ZIP 源文件变化 | 拒绝硬链接、打开后替换、同大小改写、读取中新建硬链接和观察到的父目录换链 | 真实临时文件的定序竞态回归 |

文件清理具体覆盖节点的 `source`、`sources`、文件验证路径，以及递归遍历 `config.inputs`、`initialVariables`、`assignments.value` 中的保留键 `workflowFileId`、`base64` 和绝对 `path`；`file/files` 输入默认值也会移除。同名业务 JSON 键也被视作这些保留字段，应改名。它不会扫描、改写任意文本或 ZIP 资料正文；详细规则见 [JSON 字段说明](../原理/10-JSON字段与导入导出.md)。

ZIP 的文件身份复核属于检测加固，仍不是可变父目录 TOCTOU 的完整 OS 隔离证明。完整保护需由可信 Host 注入受限 reader，或把附件读取放入已核验的隔离执行器；当前不能据此开放 Secret。

这些规则保护的是 Secret 声明通道。用户若把密钥手工写进普通提示词、普通变量、批注或公开附件，它不再是受控 Secret；导出不会推断任意文本是否是密码。

## 3. 进程生命周期补验

使用真实安装的 Harness Node 24.18.1 / Electron 44.0.0、rc.2 subprocess-local 和 MXC，在独立合成测试进程中运行；这不是桌面主/子 Agent 的完整攻击验收。

| 情形 | 实测 |
| --- | --- |
| 普通取消 | 父子均退出 |
| setsid 后取消 | 原生 waitForExit 返回 true，但子进程仍存活 |
| 父进程先退出 | 子进程仍存活并重挂到 PID 1 |
| 合成 Host 被强制结束 | 工作负载父子仍存活 |
| PID 重用 | 未通过验收，不宣称支持 |

已修复适配器的安全状态误判：原生管理范围退出不再等于全树已清空，保留 `unverifiedTreeRanges`，停止时返回明确的未核验错误；同时补齐停止锁存、迟到启动拒绝、逐项取消和等待超时/错误脱敏。

[原生探针](Secret兼容证据/生命周期原生探针.json) · [修复后适配器探针](Secret兼容证据/生命周期适配器探针.json)。所有合成残留在采样后清理，该清理不算产品生命周期能力。**未回收不自动等于已逃出 Seatbelt**；当前仍缺撤销、插件更新和 Host 崩溃的完整边界证据。

## 4. 原生凭据代理与签名条件

当前本地代理依赖尚未接管的全局 Host 隔离，不能仅解除 `controller.close()`。另一条已有的 Data Protection Keychain 代理路线可利用专属访问组与系统生物认证减少全局接管范围，但必须有经核验的发行产物。

本轮在普通用户环境只读核对到 Apple Development 身份；它不是本方案要求的 Developer ID 发行签名。不能复用 DeepSeek 主程序的发行身份，也不应把发行私钥交给 Agent。需要在 Agent 不可调用发行私钥的独立环境生成签名产物、匹配的 profile 与专属访问组。

Host 侧已补齐固定可信发行清单、签名和完整性准入，不再仅接受代理自报的 `available: true`。每次启动前核验固定 Team、Developer ID 代码要求、精确 entitlement、包内完整文件集合和哈希，签名检查后复查文件；没有工作流、环境变量或 RPC 覆盖入口。当前编入的可信清单为 `null`，所以仍保持拒绝。

真实系统 `codesign` 对当前 ad-hoc 包和固定发行要求返回 exit 3，签名要求不满足。正向准入的自动化用例使用替身合同，不能当成已取得发行签名；没有访问 Keychain 或打开凭据输入窗口。

官方依据：[Apple 关于 DP Keychain 与 profile 的说明](https://developer.apple.com/forums/thread/836816)。签名和包校验也不等于对任意同用户并发代码替换的完整防护，仍需实际录入与攻击验收。

## 6. 完成 Secret 可用性的剩余条件

用户已确认：**目前没有现成的签名 Secret Broker 安装包**。因此发行签名路线当前不能进入真实凭据录入验收；这不代表必须要求用户购买证书，也不代表把本地开发签名改名后即可替代。现有本地隔离路线仍可继续研发，但它把工作转移到真实 Harness 的全局启动与执行边界，不能靠工作流插件内的一个开关完成。

| 后续阶段 | 具体工作与通过条件 | 当前范围 |
| --- | --- | --- |
| 可信启动 | 在公共文件、子进程、Agent 和 MCP 消费者加载前安装隔离，并阻止并行加载或插件更新绕过；在真实启动链验证顺序 | 必须涉及 Harness 启动组合；仅修改工作流节点不够 |
| 完整执行覆盖 | 主/子 Agent、文件与搜索、CLI/MCP、工作流直接文件/网络/Python 访问统一受控，同时保留已授权的正常功能 | 必须逐个适配宿主入口；局部合成探针不能代表全部接管 |
| 生命周期与绕过 | 验证后台新会话、父进程先退、Host 崩溃、撤销及更新；保护安装目录、凭据库、GUI/AX、调试和 IPC 入口 | 当前存在实测缺口，未确认全部进程退出时继续拒绝凭据访问 |
| 原生凭据闭环 | 前述条件通过后，用户原生录入专用凭据，合法固定操作成功，再验证 Agent 拒读及导入导出不泄漏 | 尚未开始；不使用普通环境变量或配置文件替代 |

1. 获得并核验可信发行原生代理，或完成全局 Host 启动组合与全部可达副作用的隔离。两条路线不能用同一个 ready 布尔值混淆。
2. 由用户在原生窗口录入专用合成凭据并完成系统认证；Agent 不代输真实密钥。
3. 验证固定操作成功、取消、替换、删除、重启、主/子 Agent 拒读，以及 JSON/ZIP、快照、日志和批注中不含原值。
4. macOS 与 Windows 分开记录；Windows 未验收不应冒充当前 macOS 验收，也不作为 macOS 未启用的唯一原因。
