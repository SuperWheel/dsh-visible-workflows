# 工具调用 Agent（agent）

[返回手册总索引](../README.md) · [节点执行矩阵](README.md)

类型身份：`agent`。核对日期：2026-10-21。原生调用基础核验日期：2026-10-16；子 Agent 定义及提示词快照说明更新于 2026-10-17，本轮真实桌面结果另见[迭代记录](../验证/11-保存高级设置与子Agent定义迭代.md)。

## 用途与配置

现有 Agent 节点通过 DeepSeek Harness 原生 `spawn` 创建独立子 Agent。保留 `prompt`、`inputs`、模型/思考强度、角色预设、工具名单、步数上限和可选超时；模型默认继续使用宿主选择。原生接口不支持时明确报错。

配置面板新增“子 Agent”卡片：输入名称可搜索当前流程、当前主对话内的身份，或下拉选择；新名称未匹配已有项时点击右端“＋”创建。每个身份有独立 ID、`agent-N` 编号和工作流内唯一名称，多个节点可重复选择。同一工作流里其他对话已经绑定的身份不能直接拿来执行。

`Workflow.subAgents[].prompt` 保存共享角色；节点的 `config.subagentId` 指向该定义，`config.prompt` 是本节点的任务。这是唯一受支持的 Agent 节点结构，节点级 `config.rolePresetId` 会被拒绝，不自动转换为定义。尚未选择身份或定义缺失时保留为待配置节点，由用户选择或创建后才能运行。角色不展开变量，任务提示词支持输入引用。模型、工具和步数仍由各节点配置。一个身份复用角色配置，每次执行创建独立原生任务，不代表复用已结束任务的会话记忆。

角色预设选择、管理入口和角色文本都在此卡片内。选择预设时复制提示词为快照，后续预设修改不自动覆盖；点击“更新预设内容”才同步。也可直接编辑此身份的角色文本；同一身份的所有引用节点以后使用更新后的内容，已开始的任务保持原快照。

JSON 导出完整角色文字、任务提示词、编号和名称，移除原主对话与本地预设来源；导入重建定义 ID 并重写引用。目标环境没有原预设也保留角色正文。字段限制见 [JSON 第 5.2 节](../原理/10-JSON字段与导入导出.md)。Secret 原值仍不得进入任一提示词。

配置面板的“结构化输出”可以声明字段名称、类型和必填项；留空时沿用默认文本输出。声明字段可在下游变量选择器中引用，不必先运行节点。`text`、`json`、`steps` 保留执行器的默认含义和类型；自定义字段不能覆盖这些保留字段的类型。

`tools` 可选择当前获准的宿主工具及工作流内置/API 工具。后两类通过子 Agent 私有工具注册接入；委派其他 Agent、Worker 或工作流的工具不可用。子工作流请通过画布中的工具节点执行。

## 执行与结果

Graphon 继续负责图调度，宿主原生 Agent 负责节点任务。运行详情记录执行实例、原生任务 ID、修复任务 ID、Token 用量和验证结果。结构化字段按节点输出契约检查，`text` 为最终显示文本；旧版自循环的 `tool_results` 字段不再作为稳定输出契约。

运行记录的 `subagentDefinitionId` 表示本轮新增的工作流内身份；原有 `subagentId` 表示此次原生任务 ID。两者分开保存，不能把定义编号当成原生停止或续聊接口的参数。

停止单个 Agent 会向它发送取消信号，界面等待实际任务结束后更新。工作流取消同时停止受管任务。独立启动时创建不发起模型请求的工作流父上下文；其能力来自宿主默认配置。

运行详情中的“查看 Agent 过程”展示实际宿主事件摘要与补充指令记录，可手动刷新；它不是完整原生会话或推理轨迹。只有原任务仍运行且宿主允许时才能发送补充指令；任务已结束、开始提交结果或不支持该能力时会说明原因，不重新创建原动作任务。

补充指令先核对根运行状态和原任务身份，再向仍活动的任务投递；消息 ID 用于重复提交校验，同一 ID、内容和任务的重试不会重复投递。补充投递有独立身份，不新增模型调用或预留 Token；原任务的最终累计用量统一归集，不按补充消息虚构或重复计数，没有可靠回执时保持未知。接收回执不等于任务已处理指令，具体结果以宿主记录为准。补充指令不会扩展工具权限、重置步数或解除原模型输出限制。

## 验证与有限修复

工作流子 Agent 使用原生工具模式，选定工具在首轮请求前完成绑定。`run_code` 是通用代码执行能力，不能作为白名单工具选择；子 Agent 的实际调用入口也拒绝该能力和未授权的委派工具。主会话的工具模式不受影响。空工具修复只允许提交结构化结果，没有代码执行、读写文件或继续委派的能力。

结构化输出或最小文本长度不合格时，仅在原任务已确认完成的情况下，才可按执行策略发起最多两轮独立修复。独立画布运行默认先展示候选，由用户确认一次修复；`repairMode: auto` 仍须宿主可信授权，JSON 配置不能自行授权。修复任务没有工具，另计实际 Token 用量与调用次数，并受共享模型并发上限约束。未完成任务、未知副作用、文件缺失不自动重试。

等待用户确认、修复轮次上限耗尽、最大修复轮次设为 0 或适配器不可用时，运行暂停并保留候选输出、原因及已执行的修复尝试。初次原动作的无效输出不算一轮修复。此时普通“继续”不能重放原动作；可停止运行，或编辑候选 JSON 后选择“确认修正输出并继续”。宿主重新校验字段、长度和已配置文件要求；失败仍保持暂停并保留编辑，通过后复用该节点结果。根运行无其他待纠正输出时可继续；子运行纠正后仍保持 `paused`，不会独立启动，需要回到根运行选择“继续”，由根运行统一恢复子流程及其共享根运行上下文。

确认模型修复只增加一次修复计数；成功后仍保持暂停，需要用户继续。重复点击不重置累计次数。

文件验收分别配置“必须存在”“必须完整读取”“必须改变内容”，保存执行前后哈希和受信工具回执，不保存额外文件正文。内容变化不证明由哪个 Agent 写入。当前 Harness 未提供可验证的工具来源，必读要求会标为未验证并阻断；不能用同名 `read` 工具或 Agent 自述替代读取证据。修复必须沿用原动作证据，不能重读或跳过。文件依赖结果在恢复时仍保守失效，尚未开放基于指纹的跨运行缓存复用。验证通过不代表业务内容一定正确。未知用量不会按零消耗处理。Secret 值不可进入 Agent 输入。
