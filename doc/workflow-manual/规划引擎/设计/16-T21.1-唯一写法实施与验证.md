# T21.1 唯一写法：实施与验证

## 1、唯一写法与代码依据

- 工作流输入统一用 `{{input.字段}}`，条件左值、列表和迭代来源用裸路径 `input.字段`。`src/host/runtime.ts:51` 的 `reference` 对 input 命名空间直接读取 scope.input；`render`、`resolve`、`mapping`、`listReference`、`matches` 共用它（第 66、73、79、80、88 行）。模板、输出、模型提示词、工具和 HTTP 参数、代码 inputs、列表、iteration 和 loop 都沿此路径解析。容器构造通过 `{...scope}` 继承根输入（第 606、645 行），两层嵌套也保持一致。
- 模板正文直接引用输入或上游字段；for 和过滤器也直接读取数组、对象，无需 inputs 映射。`src/host/template.ts:14` 的表达式读取器将未命中循环局部变量的完整路径交给 lookup；`src/host/runtime.ts:683` 将其交给 reference。未发现需要为类型保留而使用 template.inputs 的例外；新规划不再教 inputs。旧映射仍完整支持，语法示例的固定值移到独立 input 夹具，避免演示旧绑定。
- CREATE 根入口用 start；一个根输出用 result；多个分支输出各用不同 key，不要求其中一个叫 result；零输出不声明 result。运行结果键只由 outputName 决定；互斥出口可同名，同时激活的出口须不同名。`src/shared/planning-authoring-core.ts:132` 只建立 start/result 到预留身份的映射，第 365–366 行移除未声明预留节点，并未要求必须声明 result；`src/host/runtime.ts:409` 按 outputName 写运行结果。EDIT 保留已有 n1/n2 身份。
- 边界：旧图如果显式配置 prompt/output 的 inputs，同名映射仍按现有逻辑覆盖 input 中的同名字段；新教学提示避免同名覆盖。code 源码不展开插值，`{{input.字段}}` 写在代码节点 inputs 中，由 main(inputs) 接收。旧图自身配置作为编辑事实保留，不把历史配置改写成新的教学规则。

## 6、模板渲染边界回归修复（2026-10-22）

真实配对复验的 80 次尝试中，template-fill 的 container 案例有 2/5 被 oracle 拒绝。记录的 repeats 0、3 把 `{{iterate.result | tojson}}` 写入 `output.text`：普通插值把过滤器当成字段名，运行失败且没有实际输出。T21.1 统一为 `{{input.x}}` / `{{upstream.field}}` 后，template.text 的过滤引用与其他字段的普通引用外观相同，使原先隐含的“完整模板语法只在 template.text 生效”边界不可见；本修复保留统一路径，不恢复 inputs 重命名。
