# 生成后自动整理画布

> 状态：2026-10-23 用户批准。来源：用户反映"生成的流程图每次打开都非常乱"，希望生成后像前端"整理画布"那样先自动整理一遍。便签模式的设想已放弃：节点说明改用节点备注（文档 19 A3），不再需要便签来安放。

## 1、现状

### 1.1、为什么生成的图乱

Host 把规划结果落成节点时，新节点的位置由 `planning-projection.ts` 第 81 行决定：

```
x = 80 + (序号 % 5) × 320，y = 120 + floor(序号 / 5) × 220
```

也就是按声明顺序排成每行 5 个的网格，完全不看连线方向、分支和节点的实际尺寸。分支多或节点多时，连线会来回交叉；容器内部的子图也用同一套网格。修改已有图时，已有节点保留原位置，新节点同样落在网格里。

### 1.2、前端已有的"整理画布"

画布工具栏的"整理画布"按钮（`canvas.tsx` 的 `arrange()`）调用 `layout.ts` 的 `arrangeNodes()`：
- 按连线的拓扑层级分列，从左到右排列；
- 用卡片的真实尺寸（`nodes.ts` 的 `nodeSize()`，会考虑分支数量和容器尺寸）计算间距；
- 有环时不会死循环，环上节点放在最后几列，方便人工修正。

整理节点后，再用 `arrangeAttachedNotes()` 把锚定便签放到所锚节点下方，并避开其他元素。这个按钮只在用户手动点击时生效。

## 2、目标

Host 生成或修改图后，把整理好的坐标直接保存。用户第一次打开就是整齐的图，不必手动点"整理画布"。

## 3、改动

### 3.1、共用一套布局算法

把 `arrangeNodes()`、`nodeSize()` 中不依赖界面的尺寸计算以及锚定便签的排列，移到 `src/shared/`（例如 `canvas-layout.ts`），前端和 Host 共用：
- 前端"整理画布"的结果与 Host 自动整理的结果完全一致；
- `nodes.ts` 目前引入了界面语言 `t`，只搬纯尺寸部分；前端改为调用共享版本，按钮行为不变。

### 3.2、整理范围（用户批准）

| 场景 | 行为 |
| --- | --- |
| 新建工作流（含模块实例化） | 整张图全部整理，每层容器子图各自整理 |
| 修改已有图 | 已有节点保持原位置，不动用户摆好的布局。新节点放在其上游节点右侧的空位（无上游时放在下游节点左侧），避开已有节点和便签。新容器的内部子图整体整理 |
| 用户手动点"整理画布" | 与现在相同 |

### 3.3、实施要点

- 在 Host 落图（projection）之后、计算候选摘要之前执行，保证候选摘要、回执和保存的图使用同一份坐标。
- 只改坐标，不改节点身份、配置、连线或执行语义。固定节点（`fixed`）不移动。
- 已有锚定便签随所锚节点移动（沿用 `moveAttachedNotes` 的语义）。新建时没有便签。
- 结果确定：同一输入每次得到同一坐标，测试可以直接比较。
- 模块固定实现的摘要（`implementationDigest`）不得因整理而变化；若整理会改变任一冻结摘要，停止实施并说明。
  - 核实（2026-10-23）：`reviewed-file-write` 的摘要 `e44821bd…` 对固定配方整图取摘要，配方节点带常量坐标 `x:0,y:0`。配方只在模块加载时取摘要，并转成不含坐标的 CREATE 声明；整理只作用于落图后的候选副本，不回写配方，所以摘要不变。
  - 模块 revise 对比实现时，只比较 id、kind、config 和连线（`definitions`），并沿用已保存节点的坐标；整理后的坐标不影响它。
  - 实施时不得修改配方坐标。

## 6、实施记录（2026-10-23）

### 6.1、共享布局与 Host 接入

- `src/shared/canvas-layout.ts` 接收原客户端的布局、尺寸及纯端口计算；`canvas-notes.ts` 接收便签尺寸、锚点随动和整理函数。客户端原文件保留兼容导出，`canvas.tsx` 的 `arrange()` 仍按原顺序调用 `arrangeNodes`、`arrangeAttachedNotes` 和视口适应，不改样式或交互。与 `745ddad` 源码逐段比较，原几何及便签整理函数原样迁移。
- `materializePlanningCandidate` 完成投影及配置默认值解析后调用 `layoutPlanningCandidate`，再返回候选供既有摘要、验证和发布路径使用。原 5 列网格不再参与新节点放置。
- 新建逐层整理循环／迭代子图；无固定节点和便签障碍时，坐标与客户端整理相同。Host 固定节点及固定容器的整个子图保持坐标；其他节点避开它们。
- 修订保留所有既有节点（包括子图节点）的坐标，按拓扑列顺序放置新增节点，优先放在已定位上游右侧 80px，无上游可用时取下游左侧。碰撞时仅向下寻找空位，避开已有节点、便签和先放置的新增节点；新容器的全新子图整体整理。已有手工重叠不通过移动旧节点纠正。
- 锚定便签使用原 `moveAttachedNotes` 偏移语义；游离便签不动。新增／移动节点及其锚定便签一并参与避让。节点尺寸不读取 T26 的 `note`。
- 创建时 Host 自有的初始入口／出口也参与整理，因此候选元数据验证允许 CREATE 的非固定节点使用新坐标；修订坐标、固定状态和已有编号检查继续保留。
