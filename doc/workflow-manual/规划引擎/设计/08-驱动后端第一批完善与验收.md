## 2、驱动选择合同

表 2-1 新任务适用范围

| 场景 | 行为 |
| --- | --- |
| 请求 legacy / compact-repair | 保持请求模式 |
| template-fill 新建或已有可用模板 | 使用 template-fill |
| 修改可编辑的既有工具，该工具没有可用模板 | 在有效模式冻结前选择 compact-repair，记录 `baseline-tool-template-unavailable` 与节点 ID |
| 固定节点、固定容器后代、明确编辑范围之外的缺模板工具 | 保留节点，不因这些节点切换模式 |
| 不支持的输入 schema、非法快照、未知协议 | 明确失败，不将异常当回退信号 |
| 权限拒绝、合同冲突、未知发布结果 | 原有拒绝或回执核对路径生效，不换协议重试 |
| 已冻结任务、旧任务澄清、重复请求、重启 | 保持该任务的协议、身份、草稿和额度，不按当前默认值重选 |

新任务先保存 pending 请求模式。上下文、模板合同和选择结果均先在局部变量中通过校验，再检查权限与取消信号，一起冻结。带有上下文、子任务、候选或计量的非法 pending 记录拒绝读取。合法 pending 在重启后转 interrupted，不自动调用模型。

已证实的回退用例是“修改缺模板既有工具的标题且保留配置”。它允许继续编辑定义，不授予工具可用性：生产 readiness 仍返回 canRun=false，实际运行入口仍拒绝。此回退不代表输出字段可猜测，也不代替 T04 的输出合同。

新记录增加 `compilerSelection`。**template5 旧二进制的 strict schema 不能读取新记录**。配置回退须使用认识此字段的兼容构建；旧二进制演练只能在备份的隔离数据上进行，不得删除活动记录字段强行降级。T11 的完整兼容演练仍待完成。

## 4、离线配对驱动的使用与限制

无模型自检：

```sh
pnpm --config.verify-deps-before-run=false run bench:template-paired --self-test
```

不传 `--run` 仅显示说明，不创建凭据桥接。真实实验要求显式 `--run --out=全新目录 --repeat=N`。本批没有执行该模式。

驱动冻结模型、思考强度、输出上限、样本、源码摘要和修复额度，两组按 AB / BA 交错串行执行，保留失败与未知用量。两种编译器最终使用相同 Graphon 业务判定。无模型自检让两组分别经历缺字段 → 同会话修复 → 两组输入执行；不将该自检写成性能结果。

当前仅覆盖已有 6 个确定性新建 / 编辑案例，未覆盖原计划 8 类任务、verified-trial / R7 来源层。整体 arm 完成后才落盘，未完成 arm 尚无逐调用持久化，不支持完整中断续跑。记录的是创作墙钟、请求往返、目录、编译和 oracle；SDK 启动、模型独占时间不可观测，保持 null。准入等待、持久化、人工等待等完整分段尚需补齐，T08 保持部分完成。T09 尚未开始，不能据此宣称提速。
