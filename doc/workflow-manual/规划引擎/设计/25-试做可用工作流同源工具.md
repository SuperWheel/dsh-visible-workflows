# 25、试做可用工作流同源工具

## 1、背景与决定

2026-10-25 决定：试做阶段开放工作流同源 HTTP/HTML 会话工具。

本次任务给出的 Desktop r24–r27 观察：execute-first 试做只有宿主会话工具 `web_fetch`，它把页面转换成文本并截断；GitHub Trending 页面在导航菜单处已经截断，仓库列表没有进入结果。r26 中，工作流 HTTP 节点能拿到约 567 KB 完整页面，超过 256 KB 的正文进入 HTTP 正文缓存，`builtin:html.select` 能提取 10 个仓库。这些是上游提供的验收背景，本次实现没有重跑 Desktop、访问 GitHub 或调用真实模型。

试做是工作流执行方式的预演，应能使用与最终节点相同的 HTTP 请求和 HTML 处理能力。保留宿主 `web_fetch`，新增三个名称明确、行为固定的会话工具，不加入自动模式选择、重试或工作流生成动作。

## 2、工具与执行路径

| 会话工具 | 对应节点 | 共用执行路径 |
| --- | --- | --- |
| `workflow_http_request` | `kind: http` | `executeHttpRequest` → `httpRequest` |
| `workflow_html_extract_text` | `kind: tool`，`builtin:html.extract_text` | `executeHtml` |
| `workflow_html_select` | `kind: tool`，`builtin:html.select` | `executeHtml` |

### 2.1、注册与目录边界

`src/host/workflow-session-tools.ts` 使用 `defineTool`、`ctx.tools.register` 和 Cordis effect 注册、注销工具；`VisibleWorkflowService.registerTools()` 接入当前会话权限检查。三个名称只含 ASCII 字母和下划线、长度小于 64，不使用 `native:`、`builtin:` 前缀，也不占用 SDK 保留名称 `run_code`。已核对安装的 SDK：注册要求名称不重复，`run_code` 不允许注册或覆盖。

工具返回结构化 JSON 对象，展示层将该对象序列化为文本。HTML 工具说明和普通参数说明直接取自 `src/shared/builtin-tools.ts`，沿用文档 23 §5.1 的中文菜单文案；只把 `html` 参数扩为“字面 HTML 字符串或缓存引用”。HTTP 工具说明明确原样响应、下载上限、缓存阈值及不自动跟随重定向。

`nativeTools()` 精确排除这三个名称。因此“Harness 已注册工具”菜单和规划工具目录不出现对应 `native:` 项；真实 HTTP 节点、两个 `builtin:html.*` 节点继续存在。没有按 `workflow_` 前缀笼统屏蔽其他工具。

### 2.2、HTTP 参数与输出

- 参数：`url` 必填；`method` 默认 GET；可选 `headers`、`body`、`timeoutMs`。
- 从 HTTP 节点执行器提取 `executeHttpRequest`，节点和会话工具共用 URL、请求头、正文的转换以及方法、超时处理；没有第二套下载实现。
- 请求限制、方法校验、HTTP(S) 协议限制和拒绝 URL 内嵌凭证均由原 `httpRequest` 执行。重定向为 `manual`，不会自动把请求转发到其他地址。
- 下载按实际解压后的字节数限制为 10,000,000 字节，不把 Content-Length 当作可信大小；请求体仍限制为 2 MB。
- 小响应返回原来的 `text`、`body`、`status_code`、`headers`，可解析的 JSON 还返回 `json`。
- 正文超过 `HTTP_CACHE_THRESHOLD`（262,144 字节）时，`text`、`body` 返回同一个 `{$cachedBody:{id,runId,bytes,sha256,contentType,preview}}` 引用；预览为 UTF-8 解码后的前 2,000 字符，不展开全文，也不另附大段 `json`。
- 复用原 HTTP 实现的响应头过滤，去除 `set-cookie`、`authorization`、`proxy-authorization`。缓存读取后的结果和错误继续经过现有缓存全文压缩、脱敏方法。
- 不接受受保护凭据操作的节点配置，不调用 Secret broker；只提供普通 HTTP 节点已有的公开请求能力。

### 2.3、HTML 参数与输出

会话工具直接调用 `executeHtml`。字面 HTML、缓存读取、正文提取规则、CSS 选择器、链接补全、字段限制、输出大小限制与取消检查均使用原实现，不执行脚本、不访问网络。

`html` 可传 HTTP 工具返回的 `text` 或 `body` 缓存引用。读取通过 `WorkflowStorage.readCachedBody`，校验调用归属、文件身份、元数据、字节数及 SHA-256。不能以同一个引用读取另一个会话、另一个工作区或真实工作流运行的缓存。缓存被清理后明确报错，调用方需重跑 HTTP 请求。

## 3、缓存归属和清理

### 3.1、临时身份

每个“实际调用会话 ID＋解析出的工作区 ID”对应一个 Host 生成的 UUID 缓存运行身份。试做子 Agent 使用自己的会话身份，与父会话及其他试做隔离。调用方不能指定或切换缓存 owner。

临时 owner 只记录缓存需要的 `id/status/startedAt/endedAt`，保存在内存中，不创建伪工作流图，不写入工作流运行历史、运行事件或持久会话归属。`HttpBodyCache` 接收真实运行和临时 owner 的联合视图，所有正文仍写入同一个缓存目录，使用同一组 `httpCacheLimitMB`、`httpCacheImmediateCleanup` 设置。

### 3.2、有限租约

不能在 HTTP 调用返回时立即结束缓存 owner，否则“立即清理”设置会使下一次 HTML 调用拿到失效引用；也不能把整个会话永久标成活动运行。

采用 5 分钟空闲租约：

1. 调用开始时将 owner 标为 `running`，取消旧空闲计时器，增加正在执行的调用计数。
2. 最后一个调用结束后释放内存中的已展开正文，并开始 5 分钟空闲计时；后续调用重新续租。
3. 空闲到期后将 owner 标为 `success` 并记录结束时间，解除活动保护，执行原缓存清理规则。这里的 `success` 只表示缓存租约结束，不是业务成功或试做验收结果。
4. 取消后的最后一个调用或插件关闭时立即结束租约；插件关闭同时取消正在执行的 HTTP/HTML 操作。仍在执行的并行调用不因另一个调用结束而提前失去缓存保护。

活动租约与活动工作流运行一样暂不淘汰，因此活动正文总量可能暂时超过设置的配额；这沿用原规则，并未另建无配额缓存。空闲结束后，开启立即清理则删除正文；默认设置下可保留，并按原规则参与最早结束 owner 的配额淘汰。随后同会话重新调用可以复用尚未淘汰的引用，但不保证历史缓存持续可用。

计时器 `unref`，不会独自阻止进程退出。清理失败保留错误，下次调用报告失败，不无限保留 `running` 状态或吞掉异常。

### 3.3、关闭与重启

正常存储关闭时移除临时 owner，再调用同一个缓存清理器删除孤儿目录。异常进程退出后，临时 owner 不会从磁盘恢复；下次 `WorkflowStorage` 初始化时，原启动清理会删除没有真实运行记录的缓存目录。真实工作流运行的缓存归属和历史保留规则不变。

## 4、权限与取消

- 三项工具都要求当前存活 Agent，并从宿主解析工作区；不允许借用已结束会话的对象。
- 三项工具统一经过已有 `assertMutable`：规划模式和只读模式拒绝执行。HTML 虽不访问网络，也沿用本组执行工具的权限边界。
- 调用前检查权限和取消；调用完成后重新核对权限、会话及工作区，避免在权限或工作区变化后继续交付结果。
- 执行信号合并工具调用信号和插件生命周期信号；HTTP 再由原实现合并请求超时。HTML 仍使用解析、遍历中的现有取消检查。
- 不新增授权弹窗、不扩大权限。SDK 的会话工具限制及试做驱动的父会话授权、冻结 schema、子会话白名单继续生效。

## Desktop r28 复测发现与修正（2026-10-25）

- 试做确实改用了 `workflow_http_request`（10 次）和 `workflow_html_select`（9 次），没有再用 `web_fetch`，首次抓取拿到完整 566,964 字节页面。
- 但模型把缓存引用写成 JSON 字符串，并且只保留 `id`/`runId`，丢掉了 `preview` 等字段。HTML 工具把它当成 HTML 正文处理，7 次都返回 0 条。模型随后改用 Range 分片绕道，试做公开记录涨到 58 条、约 38 KB，最终触发 `TRIAL_EVIDENCE_TOO_LARGE`。
- 修正：会话 HTML 工具接受字符串形式或精简形式的引用（`{"$cachedBody":{"id":…}}`，或同时带 `id` 和 `runId` 的对象）。
  - 只按 id 还原本租约内 `workflow_http_request` 发出的完整引用，再走与节点相同的读取和校验。
  - 找不到对应引用时明确报错，提示重新请求。
  - 完整引用、普通 HTML 正文和非引用 JSON 文本按原路径处理。
  - 工作流节点本身不变。
- `TRIAL_TOOLS_INVALID` 回执新增 `useInstead`：在当前会话可用的前提下，把节点工具 ID 对应到会话工具名（如 `builtin:html.select` → `workflow_html_select`，`native:write` → `write`），一次修正即可。

## 会话内联上限与模板预取（2026-10-25，r28 第二次试做）

- **现象**：主 Agent 自行重试了一次试做。这次 agent 用 Range 只抓了约 127 KB，低于 256 KB 的缓存门槛，于是全文直接返回。DSH 会话嫌它太长，转存成临时文件；agent 又把这个文件路径当作 `html` 传给 `workflow_html_select`，结果 0 条。之后它把上一次试做留下的报告原样写回，并在说明里承认提取这一步没有跑通。
- **修正一：会话内联上限**。`workflow_http_request` 在会话中的内联上限改为 32 KB（`SESSION_HTTP_INLINE_LIMIT`）：
  - 超过 32 KB 的正文，按运行时对 HTTP 节点的同一后处理写入缓存，返回 body 引用，并去掉 `json`；
  - 工作流节点仍按 256 KB 门槛处理，HTML 工具对两种来源给出相同结果。
- **修正二：模板预取**。生成搭图的第一轮请求花了约 200 秒，只是为了查询 `if` 模板：试做提炼的方法要求机械核对，原请求里却没有“条件/判断”字样。因此来自试做的搭图（`source.kind==='verified-trial'`）会一并预取 `if` 和 `code` 模板（`REHEARSAL_TEMPLATE_KINDS`），并附上对应的运行语义；其他请求的预取不变。
