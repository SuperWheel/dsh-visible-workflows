## 1、工具输出合同

Host 从当前调用者可见工具注册中读取输出 schema，冻结来源、版本与摘要。原生工具的 SDK 外层包装与工具自己的 value 内部字段分别说明。已执行试做最多提供两份完整成功样本，标记为观察证据；样本不能升级为任意输入的结构保证。

发布时只复核候选实际使用的合同。漂移返回 `TOOL_OUTPUT_CONTRACT_CONFLICT`，不通过切换协议绕过；旧任务缺少新元数据时维持旧合同。未知字段仍然未知，不猜测 `result`、`json` 或 `value.text`。

相关实现：`planning-tool-outputs.ts`、节点模板、PlanningContext、Host 规划上下文与发布门禁。真实冻结快照包含 50 份合同（37 native、9 builtin、4 workflow），read 两份及 write 一份样本来自指定试做 child 的完整成功调用对；11 项专用回归包含在全量 1,996 项中。发布漂移阻断有离线合同测试，未在 Desktop 人为改变宿主注册。二次脱敏导出的 write 输入摘要不能独立复算，未将其误作额外证明。详见[T04 复核](../../../../docs/evidence/backend-batch2-20261019/t04-acceptance-summary.md)。可信文件读取来源仍按 T07 保持未开放，与本批输出 schema 不混为一项能力。
