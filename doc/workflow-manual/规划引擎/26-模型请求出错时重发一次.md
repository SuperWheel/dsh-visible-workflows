# 模型请求出错时重发一次

核对日期：2026-10-26。对象：仓库当前版本（未安装到 Desktop）。

[规划引擎索引](README.md) · [子 Agent 生命周期与工具隔离](05-子Agent生命周期与工具隔离.md) · [先执行验证再生成工作流](18-先执行验证再生成工作流.md) · [试做方法的直接接收](25-试做方法的直接接收.md)

## 1. 解决什么问题

试做和规划的子 Agent 每走一步，都要向模型发一次请求。以前这次请求只要出错，整个试做或规划就直接失败；DSH 自带的重试也被挡住了。

2026-10-26 Desktop 上用 deepseek-flash 试做，四个业务步骤全部成功：抓取、抽取、写文件、回读。最后一步提交结果时，模型输出的 JSON 写到一半就结束了。DSH 报 `MALFORMED_RESPONSE`（“tool input is invalid JSON”），试做失败。用户重试后成功，但整轮重做多花了 3 分多钟。

## 2. 什么情况下重发

这次请求的回复无法使用，而且没有执行任何工具时，Host 让 DSH 在同一步里再发一次。历史不变，已完成的动作不会重做。

| 错误码 | 含义 |
| --- | --- |
| `MALFORMED_RESPONSE` | 回复格式坏了，例如工具参数 JSON 不完整 |
| `STREAM_CLOSED` | 回复流没结束就断开 |
| `EMPTY_RESPONSE` | 空回复 |
| `RATE_LIMIT`、`SERVER`、`TIMEOUT`、`TRANSPORT` | 限流、服务端错误、超时、网络错误 |

额度不足、凭据错误、上下文超长等其他错误，仍然直接失败。

## 3. 上限

- 同一步最多重发一次。重发后再出错，就按原来的方式失败。
- 重发计为一步：试做计入步数和防循环上限；规划还要再过一次步数、输入体积和用量登记（`beforeStep`）。达到上限就不再重发。
- 如果 DSH 的重试插件愿意重试这个错误，先按它的等待间隔等待；它的决定不能放宽“一步一次”的上限。
- 规划记录 `model-request-retry` 指标，并多记一次 `model-request`。
