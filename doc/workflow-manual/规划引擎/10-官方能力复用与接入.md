# 官方能力复用与接入

核对日期：2026-10-17。[返回规划引擎索引](README.md)

当前实现采用本项目自己的图规划服务，复用官方受控子 Agent 接口，保留 Graphon 业务调度。官方 workflow 包和社区 `@dsh-external/workflow` 都围绕脚本编排，未被导入为当前图规划引擎的运行依赖。

## 三方能力如何取舍

“✅”表示当前方案采用的来源；“借鉴”只表示设计方法来源，不表示已经调用该包。

| 能力 | 本项目 | 社区包 `@dsh-external/workflow` | 官方包 | 当前采用方式 |
| --- | --- | --- | --- | --- |
| 可编辑节点图与当前 JSON | ✅ Workflow、节点配置及导入导出 | 产出 JavaScript 编排脚本 | workflow 执行脚本及元数据 | 以项目字段和校验作为唯一契约 |
| 生成阶段和有限修正 | ✅ PlanningService 实现阶段与上限 | ✅ 借鉴调查、结构化生成及修正方法 | 提供底层 Agent 能力 | 独立实现，当前支持 distill（对话提炼）及 author/repair |
| 子任务启动、结构化输出、清理 | 项目 adapter 限制身份和工具 | 旧适配方式不能直接复用 | ✅ `subagents.startActivation` | 通过 `createPlanningAgent` 接入 |
| 工具真实性与范围保护 | ✅ 冻结目录、固定节点、目标范围、版本检查 | 不具备本项目的画布约束 | 提供工具 schema 与执行保护接口 | Host 校验及精确 child guard |
| 保存、修改提案、重启恢复 | ✅ 现有存储扩展原子回执 | 不提供本项目提案事务 | 不直接管理本项目图和提案 | 沿用 Host 保存路径 |
| 业务图调度 | ✅ 继续使用 Graphon 桥 | 脚本自身编排 | workflow 也属于脚本运行路径 | 图只交给当前 Runtime/Graphon |
| 当前对话历史证据 | ✅ 调用者归属、脱敏裁剪和步骤来源校验 | 不采用脚本录制回放 | ✅ session-query.observeSession 固定截面 | 只读取当前根对话；缺少服务时明确拒绝 |
| 专门资料调查 scout | 尚未实现 | 可参考调查模式 | 可提供底层子任务能力 | 当前通过澄清收集缺失资料 |
| 官方 workflow/PTC 后端 | 执行方案 P7 后置 | 不作为替代依赖 | 有脚本编排与程序化工具调用能力 | 当前未接入 |

## 新版官方包的核对结论

本轮构建审计记录的实装 Desktop 为 `0.2.1-rc.2`，项目编译 SDK 为 `0.2.1-rc.1`。相关 12 个源文件在官方两个固定 tag 下 SHA-256 一致；这只证明审计所列文件一致，不能推导整个 SDK 或安装包完全相同。

与此前 `0.2.0-rc.2` 基线相比，子 Agent 的管理实现发生变化，规划 adapter 使用新版 activation 接口。官方 workflow 的启动数据仍为 `script/meta/args/parent/signal`，`phases` 是脚本进度分组，不是本项目画布节点。workflow-ptc 已采用 activation，但仍不能直接提供本项目的节点范围、固定保护及发布事务。

审计同时保留不存在路径的 404 结果，不把这些条目计入摘要相同比对。版本与文件详情见[官方包审计记录](../../../docs/evidence/workflow-official-021-audit.json)。这是一份固定版本的构建依据，不承诺未来升级继续兼容。

## 当前接入的官方契约

`createPlanningAgent` 从 Host 取得 `subagents` 服务，检查 `spawn` provider 不继承父会话上下文，并支持 `agentOptions`、`outputSchema` 和深度限制，然后才启动子任务。

```typescript
// 接口形状示意；具体参数及退出处理以 agent.ts 为准。
subagents.startActivation({
  provider: 'spawn',
  label,
  childId,                 // Host 预先分配，用于首轮组装前精确限制
  request: { parent, prompt, agentOptions, outputSchema, maxDepth },
  signal,
  delivery: 'caller',
})
// 返回句柄包含 childId、result、dispose()
```

`delivery: 'caller'` 让结果返回当前规划调用。当前工具同步等待一个受控处理阶段，等待用户澄清时返回主 Agent；未启用后台 job 自动继续授权。官方 child 支持续聊，本引擎每次 distill/author/repair 都新建 activation 并显式清理，不恢复上一轮 child。

权限保护由项目 adapter 在首轮提示组装前配置，不能靠旧 `toolFilter/persona` 参数或一条提示词代替。参数详情和取消边界见[子 Agent 生命周期与工具隔离](05-子Agent生命周期与工具隔离.md)。

## 官方会话查询如何接入

Host 对 `sessionQuery.observeSession` 做能力检查，传当前根会话身份及 `projectionMode:none`，读取一个固定 observation 并在 finally 中释放。显式声明 peer 及编译依赖 `@deepseek-ai/dsh-session-query`，当前编译版本为 `0.2.1-rc.1`。该服务可以查询宿主全部会话，本项目在调用前及等待返回后自行复核权限，不能把查询服务当作授权机制。

证据读取采用公开事件白名单，不使用废弃 snapshotEvents API，不展开其他会话。见[官方查询实现](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.2/packages/session-query/session-query/src/index.ts)、[固定 observation](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.2/packages/session-query/session-query/src/observation.ts)及[当前采集器](../../../src/host/planning/conversation-evidence.ts)。

## 下次升级应核对哪里

1. 分别记录实装 Desktop、编译 SDK、官方固定 tag；保留源码审计范围。
2. 核对 provider 能力、child 创建事件顺序、首轮提示组装、结构化输出和工具执行 guard。
3. 核对 `signal`、`result`、`dispose` 的取消与清理语义；不要只根据 TypeScript 编译通过判断兼容。
4. 运行 adapter、Host 接入、发布和共享准入回归；真实模型与安装后体验另留证。
5. 仅在确有需要时评估官方脚本后端；不得以接入脚本包绕过当前 Workflow 校验和发布路径。
