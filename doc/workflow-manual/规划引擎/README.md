## 一条主线

```mermaid
flowchart LR
  A[用户发送需求] --> B[Host 核对身份和基线]
  B --> C[受控子 Agent 提交局部编辑]
  C --> D[Host 编译并校验]
  D --> E[保存新图或生成修改提案]
  E --> F[用户发起业务运行]
  F --> G[WorkflowRuntime 与 Graphon]
```

**照试做生成节点图（2026-10-26，r42）：** 新建任务来自已验证试做时，Host 先直接接收试做提交的方法（[25](25-试做方法的直接接收.md)），再把跑通的调用换成骨架节点（[22](22-试做路径搭成骨架.md)），从写出的文件反推模板（[23](23-写出文件反推渲染模板.md)），补成预先编译过的完整草稿（[24](24-完整草稿的组装与预编译.md)）。作者可以原样提交，也可以写明理由后修改。其中任何一层有一处不对时，只改这一处，不整体重做（[27](27-骨架出错只改出错的部分.md)）。Desktop B 轮从 18.9 分钟（r40）降到 11.1 分钟（r42），A 轮最快 6.0 分钟（r41）。

需要开发接入时，按 **01 → 02 → 13 → 03 → 04 → 05 → 08** 阅读；排查卡住、取消、重启或用量问题时，按 **06 → 07 → 09** 阅读。状态为 `ready` 只表示候选已通过规划校验；`published` 必须结合回执区分新图已保存和修改提案已发布，提案当前接受状态须另查提案；是否可执行还要看 readiness。
