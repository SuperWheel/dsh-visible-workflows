# 写出文件反推渲染模板

核对日期：2026-10-26。对象：v0.0.2 r42（提交 `5bdfc26`）。设计见[设计 26 §6](设计/26-照试做搭骨架.md)。

[规划引擎索引](README.md) · [试做路径搭成骨架](22-试做路径搭成骨架.md) · [完整草稿](24-完整草稿的组装与预编译.md)

## 1. 解决什么问题

骨架能定下抓取、提取和写入，但写入前的“整理正文”节点（render）定不下来：最终文件长什么样，只有试做真正写出的那份文件知道。作者如果自己重写模板，要思考格式、序号、链接写法，容易和试做的结果不一致。

反推的思路是：试做写出了文件，也拿到了提取的记录，两者逐字对照，就能还原出“每条记录套哪个模板”。还原出的模板必须能用同一个模板引擎重新渲染出原文件，否则不采用。

## 2. 输入

| 输入 | 来源 |
| --- | --- |
| 写出的文件正文 | 试做 `write` 调用的 `content`；调用被截断时，取能解码的前缀 |
| 记录 | 最近一次 `workflow_html_select` 的结果 `items`；结果被截断时，只取完整的记录 |
| 条数上限 | select 调用的 `limit` |

## 3. 步骤

以下面的文件为例，记录是 `{name:'a / x', link:'https://github.com/a/x', description:'Alpha'}` 等三条：

```text
# Trending Top 3

1. a/x — Alpha（https://github.com/a/x）
2. b/y — Beta（https://github.com/b/y）
3. c/z — Gamma（https://github.com/c/z）
```

1. **找每条记录从哪一行开始。** 对每条记录，从上一条的下一行起，找第一行含有它任一字段值的行。字段值可能被整理过，所以连同整理后的写法一起找（见第 4 节）。
2. **确认每条占的行数相同。** 相邻两条的起始行之差就是每条的行数，所有记录必须等距。至少要有两条记录。
3. **取第一条记录那几行作为模板正文。**
   - 行首是 `1.`、`1)` 或 `1、` 时，序号换成 `{{loop.index}}`。
   - 字段按“写出来的样子”从长到短替换成引用：先换长的，名称就不会被误换进链接里。每处出现都要换，因为同一字段可能出现两次，例如链接既作文字又作地址。
4. **检查剩下的字面文字。** 里面不能残留模板语法；至少要有一个字段引用。
5. **验证。** 用同一个模板引擎 `renderDataTemplate` 渲染已知记录，结果必须和文件对应位置逐字相同。
6. **数后面还有多少条同格式的块。** 把字面文字之间的字段位置当成“任意内容”，从第一条开始连续匹配。总数必须等于 `limit`。
7. **头尾。** 第一条之前是头部，最后一条之后是尾部，两者原样保留。

上例得到的一行模板：

```text
{{loop.index}}. {{item.name | default("") | replace(" / ", "/")}} — {{item.description | default("")}}（{{item.link | default("")}}）
```

## 4. 整理过的字段

试做写文件前常会整理字段，例如把 `makecindy / cindy` 写成 `makecindy/cindy`（Desktop r41 B）。原值对不上时，依次试模板过滤器能表达的几种整理，用第一种对得上的，也就是最简单的那种：

| 整理 | 过滤器 |
| --- | --- |
| 去首尾空白 | `trim` |
| 斜杠两侧去空格 | `replace(" / ", "/")` |
| 转小写 | `lower` |
| 以上任意组合 | 按上表顺序串起来 |

引用里会带上这个过滤器。整理后的结果仍要经过第 5 步的逐字验证，所以不会因为猜错整理方式而产出错误模板。

## 5. 截断的写入

写入记录很长时，公开证据只保留前一段，末尾附有「摘录：原记录未完整保留」标记。这时：

- 去掉标记和末尾不完整的转义，再解码出能读的前缀。
- 最后一行可能写了一半，不参与定位。
- 只用截断前完整出现的记录核对，至少两条。
- 尾部未知，不去猜；条数取 `limit`，并且要求 `limit` 不少于已数到的块数。
- 草稿的 `open` 里注明“写入记录被截断”，提醒作者需要时按需求补结尾段。

## 6. 什么时候放弃

任一步对不上就不反推，render 退回 `{{select.text}}` 一类占位，并在 `open` 标注 `verified=false`，交作者按需求改写。常见情形：

- 每条格式不一致，或行数不等距；
- 字段经过了模板表达不了的加工，例如翻译或截断描述；
- 只有正文提取（`extract_text`），没有逐条记录；
- 渲染结果与原文件不是逐字相同；
- 条数与 `limit` 不符。

反推成功时，`open` 写明“前 N 条记录逐字一致、共 M 条同格式（verified=true）”。草稿的 check 节点还会多一条条数核对。
